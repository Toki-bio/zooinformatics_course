08Measuring assembly quality

An assembler always produces a FASTA file, even from bad data. This section shows how to decide whether that file is any good. Quality has three separate sides, often called the 3C: contiguity (how few pieces), correctness (how few errors) and completeness (how much of the genome is there). One number never covers all three, so a report always needs at least one measure of each.

Contiguity
How long the pieces are. Measured by N50, NG50, auN, number of contigs and gaps. Tools: gfastats, QUAST, seqkit stats.
Correctness
Are the bases right, and are the pieces joined in the right order? Measured from the reads: Merqury QV and k-mer spectra; reads mapped back to the assembly (Inspector, CRAQ, Flagger; part 4 below); the Hi-C contact map.
Completeness
How much of the genome is in the file. Measured by k-mer completeness (Merqury), conserved genes (BUSCO, section 10), and the assembly size compared with the expected genome size.

First rule: write down which file each number belongs to. Assemblers write several FASTA files (primary, alternate, hap1, hap2), and pipelines write one after every step (raw, polished, purged, scaffolded). A QV from one file and an N50 from another do not describe one assembly. In our report on species B and C (two unpublished small-mammal genomes), BUSCO and QV had been measured on the polished file but size and N50 on the later purged file, and the first draft mixed them. In the species A project (an unpublished rodent genome), every "hifiasm" number first sent to collaborators came from haplotype 1, because a script picked the first matching file name (section 07 explains the file names). Check the sequence names inside the file before you report anything.

1 · Contiguity: how many pieces, and how long

Lesson 1 explains N50, L50, NG50 and auN with an interactive ruler (lesson 1, Measuring contiguity). Here we add what matters once you have a real assembly.

  • Contigs and scaffolds. A contig is a stretch of sequence with no unknown bases. A scaffold is a chain of contigs joined in a known order, with runs of N (unknown bases) between them. These N-runs are called gaps. An assembly without scaffolding has contigs only, and its contig N50 equals its scaffold N50. After Hi-C scaffolding (section 05) the scaffold N50 can jump from megabases to whole chromosomes while the contig N50 stays the same. Always report both.
  • Gap length is often a placeholder. Many scaffolders write a fixed number of N (100 is common) when the true distance is unknown. Count the gaps, but do not read their length as a measured distance.
  • NG50 instead of N50 when comparing assemblies. NG50 uses the expected genome size as the ruler, so an assembly cannot look better by dropping small contigs or worse by carrying duplicated copies. Give the tool the expected haploid size from GenomeScope or a close relative.
  • auN is the area under the Nx curve (Σ length² ÷ Σ length). QUAST's manual recommends it over N50 when you want a single number, because it uses the whole curve and does not jump when one contig is joined or broken.
  • Length cut-offs differ between tools. QUAST ignores contigs shorter than 500 bp by default (--min-contig), and its --large mode raises this to 3,000 bp. seqkit and gfastats count every sequence. So the same file gives slightly different N50 values in different tools. State the cut-off.
# gfastats 1.3.x: contig, scaffold and gap statistics; NG50 when the expected size is given
gfastats asm.fa 2500000000
gfastats asm.fa 2500000000 --nstar-report        # full N10..N100 and NG table
gfastats asm.p_ctg.gfa --discover-paths          # hifiasm GFA graphs have no paths defined

# QUAST 5.3: --large = mammal-size settings (contigs >= 3 kb); --split-scaffolds adds a version broken at runs of >= 10 N
quast.py asm.fa --large --est-ref-size 2500000000 -t 16 -o quast_asm

# seqkit: quick table with N50 (and N90 with -N 90)
seqkit stats -a -T asm.fa

gfastats prints contig and scaffold blocks separately. Part of its report on a tiny test file from its repository:

# scaffolds: 5 Scaffold N50: 15 Scaffold auN: 12.00 # contigs: 8 Contig N50: 12 Contig auN: 8.50 # gaps in scaffolds: 6 Total gap length in scaffolds: 10

Five scaffolds contain six gaps, which break them into eight contigs. If the contig and scaffold lines are identical, the assembly has no gaps (no scaffolding was done).

In our projects: species B and C (QUAST, contigs ≥ 3 kb; values rounded). Both are contig-level (no Hi-C, no scaffolding), so there are no gaps: QUAST reports 0.00 N per 100 kb.

2 · Correctness of the bases: Merqury QV

Merqury checks an assembly against the k-mers of the reads, without any reference genome. The idea is simple. Count all k-mers in accurate reads of the same animal (lesson 1, step 3). Then cut the assembly into k-mers too. A true assembly k-mer must occur in the reads. An assembly k-mer that never occurs in the reads most likely contains an error. These are called asm-only k-mers.

One wrong base spoils all k-mers that overlap it, up to k of them. Merqury therefore converts the share of asm-only k-mers into a per-base error rate with the formula below (Rhie et al. 2020; the same lines are in eval/qv.sh of Merqury 1.4.1):

P(a k-mer is correct) = 1 − Kasm-only ÷ Ktotal
P(a base is correct) = (1 − Kasm-only ÷ Ktotal)1/k
error rate E = 1 − (1 − Kasm-only ÷ Ktotal)1/k
QV = −10 × log10(E)

Ktotal is the number of k-mers in the assembly, and Kasm-only the number of those missing from the reads. Both are counted with repeats (a k-mer present three times counts three times).

Calculator

From asm-only k-mers to QV

The default numbers are the Arabidopsis thaliana Col-0 haplotype in Merqury's own tutorial (k = 18), which reports QV 35.1183 and error rate 0.000307729. Change Kasm-only and watch the QV: halving the number of errors raises QV by about 3.

What Merqury QV cannot see. The method assumes two things: that every true k-mer of the genome is in the reads, and that the reads hold few false k-mers. The Merqury paper states both limits. If coverage is low, true k-mers are missing from the reads and QV is underestimated. If the reads carry many errors, an erroneous assembly k-mer may also be found among the read errors, and QV is overestimated. Two practical consequences follow:

  • Use accurate reads from the same animal. The Merqury authors recommend Illumina short reads (PacBio HiFi also works; the EBP standard names "Illumina or PacBio CCS", CCS being HiFi). The EBP also advises reads independent of those used to build the assembly. Reads also used for polishing make the QV less independent: the polisher has already made the assembly agree with them.
  • Systematic errors are invisible. If the reads themselves make the same mistake at the same place every time, the wrong assembly k-mer is present in the reads, so Merqury counts it as correct. Nanopore-type reads miscount long runs of one base (homopolymers, e.g. CCCCCC), and they do it repeatedly at the same tract. QV from such reads misses these errors.
  • QV says nothing about missing sequence. It only penalises wrong k-mers. A file that holds half of the genome, with no errors in that half, gets a perfect QV. That is why completeness is measured separately.

Merqury also writes the positions of asm-only k-mers (*_only.bed, *_only.wig). Load them in a genome browser: errors that cluster in one place often mark a misassembly, not scattered base errors.

In our projects: QV numbers and how far to trust them.
  • Species B and C, short-read 21-mers. In both, QV rose by about 3 units from Medaka to NextPolish (the error rate roughly halved); C stayed a few units below B, and both stayed below QV 40. These were measured on the polished file before purge_dups, with the same short reads that NextPolish used for polishing, so they are not independent in the EBP sense. They are still useful for the before-and-after comparison: the error rate halved while BUSCO did not change.
  • Species A, long-read 21-mers. No short reads exist for this animal, so Merqury was run with the long reads, which carry about 1 % errors. The hifiasm primary scored a far higher QV than the Flye + Medaka assembly. This ranks the two assemblies, but it is not an absolute accuracy. A separate estimate from variant calling on the same reads gave a QV in the low 40s. That estimate counts only errors that the reads contradict, so the true error rate can only be higher.
  • Homopolymers. In species A exons, hundreds of indels contradicted by the reads were found, about nine in ten of them in homopolymers. In the mitochondrial genome, at a depth of thousands, the read majority itself undercalls a C-run in one gene, and polishing with the same reads keeps the error. Merqury with these reads cannot detect such sites. This is why Illumina reads of the same animal were judged necessary for gene-level work.
  • QV vs completeness. Species A hap1 had almost the primary's QV but a BUSCO about 8 points lower: its bases were as accurate as the primary's, but sequence was missing.

3 · Completeness and copy number from k-mers: the spectra-cn plot

k-mer completeness is the reverse question: what share of the reliable read k-mers is found in the assembly? Merqury first removes the low-count error k-mers from the read set (it finds the cut-off between the error peak and the first true peak automatically). What remains are called solid k-mers:

k-mer completeness = solid read k-mers found in the assembly ÷ all solid read k-mers × 100 %

A primary (pseudohaploid) assembly keeps only one copy of each heterozygous region, so it cannot contain the other allele's k-mers and its completeness stays below 100 % even when nothing is wrong. In Merqury's tutorial each of two A. thaliana haplotype assemblies scores about 84 %, and the two together score 98.3 %.

The spectra-cn plot (copy-number spectrum) joins both views. It is the read k-mer spectrum from lesson 1, with each k-mer coloured by how many times it occurs in the assembly: grey = 0 times (read-only), red = once, blue = twice, green = 3, purple = 4, orange = more than 4. A thin bar at the very left (x = 0) shows asm-only k-mers, the errors. The x-axis is how often the k-mer occurs in the reads; on it, heterozygous k-mers form a peak at the single-copy coverage c, homozygous k-mers at 2c, and a two-copy repeat at 4c.

Simple explanation with examples: reading a real spectra-cn plot

Read the plot peak by peak, and ask for each one: which colour should it be?

peak where (reads) primary assembly both haplotypes (hap1+hap2) het c half grey, half red red (each allele once) hom 2c red (once) blue (once per haplotype) repeat 4c, 6c ... blue, green ... purple, orange ... errors left wall grey grey asm-only bar at x = 0 should be tiny should be tiny
  • Grey under the het peak (at c) in a primary assembly is normal: the other allele is not supposed to be there. In a two-haplotype assembly it means one haplotype is incomplete.
  • Grey under the hom peak (at 2c) is never normal: sequence present in both parents is missing from the assembly.
  • Blue under the hom peak in a primary assembly means false duplication: a region was assembled twice, usually because the second parental copy was kept as an extra contig. purge_dups (section 06) removes these.
  • Red at 4c, 6c (or blue at 4c in a two-haplotype assembly) means repeat copies were collapsed into fewer copies than the reads say.
  • A tall bar at x = 0 means many base errors; polishing should shrink it.

spectra-asm is the companion plot for two files (hap1 + hap2, or primary + alternate). It colours read k-mers by which file they occur in: only in the first, only in the second, or in both. For a good pair, the het peak (c) is split between "only in hap1" and "only in hap2", and the hom peak (2c) is "in both".

In our projects: the species A primary. Its copy-number spectrum (long-read 21-mers) has one main peak; the heterozygous shoulder at about half that depth is not resolved. Around the main peak, only about 1 % of the k-mers are present twice in the assembly and nearly all the rest once: little false duplication, in line with a low BUSCO Duplicated (a few percent). Its k-mer completeness is above 90 %, and hap1 alone reaches several points less. The primary is several percent larger than the Flye + Medaka assembly and the published genome of a close relative, and the k-mers do not explain the difference; purge_dups was left as an optional test.

  • out.completeness.stats: assembly, k-mer set, solid k-mers found, all solid k-mers, completeness %.
  • *.spectra-cn.{st,fl,ln}.png (stacked, filled and line versions of the plot), *.spectra-asm.*.png, *_only.bed and *_only.wig (error positions).
  • Merqury needs meryl, Java, R (argparse, ggplot2, scales), bedtools and samtools. Database names must end in .meryl. Its tutorial says a 3 Gb genome takes up to 8 hours on 24 cores on one machine. The bioconda package is version 1.3; the README recommends the newer 1.4.1 from GitHub.

4 · Correctness of the structure: map the reads back

k-mers see short errors. Wrong joins, collapsed repeats and missing pieces are larger than a k-mer, and show up when you map the reads back to the assembly and look at how they lie.

  • Mapping rate. Almost all reads of the same animal should map. A low rate means missing sequence (or contamination in the reads). samtools flagstat prints it.
  • Coverage along the assembly. Most of the assembly should sit near the median depth. Regions at half depth are a single haplotype, a falsely duplicated copy, or a sex chromosome present once (X or Y in a male). Regions at double depth or more are collapsed repeats. samtools coverage gives depth per sequence.
  • Clipped reads. At a wrong join, reads stop aligning partway and the rest of each read is "clipped" off. Many clipped reads at one point mark a breakpoint.
  • Hi-C contact map. For scaffolded assemblies, the Hi-C heatmap is the main check for wrong joins and inversions between contigs (section 05).

Three tools turn these signals into lists of suspicious regions. Each is reference-free.

In our projects: depth tells the sex. In the species A primary, about three quarters of 10-kb windows lie at 0.75–1.25 × the median depth. More than 100 Mb of contigs sit at half depth and have no counterpart elsewhere in the assembly; most of their alignment to the published genome of a close relative falls on one chromosome. These are the single X (and Y) of a male, not an assembly error. Half depth alone cannot tell a sex chromosome from a haplotig; the missing partner copy and the alignment can (section 12).

5 · Completeness: genes, size, chromosome ends

  • Conserved genes. BUSCO counts how many of a fixed set of genes expected once in every species of a group are found complete, fragmented or missing (section 10). It complements k-mers: k-mers see every base but not genes; BUSCO sees genes, but only a few thousand of them.
  • Size against expectation. Compare the assembly length with the GenomeScope estimate and with a published relative. Much larger suggests false duplication or contamination (section 09); much smaller suggests collapsed repeats or missing sequence. Remember that k-mer estimates from long reads tend to be low (lesson 1).
  • Telomeres. A chromosome assembled end to end carries the telomere repeat (TTAGGG in vertebrates) at both ends. The EBP standard includes "> 50 % telomere/telomere-like structure completeness" among its additional criteria.
In our projects. The species B and C assemblies are about a fifth larger than the 2 Gb guess given to Flye; that guess was never checked against a published genome size. The species A primary is about a tenth larger than its GenomeScope estimate and several percent larger than the published genome of a close relative. Of its hundreds of contigs ≥ 200 kb, none carries a telomere repeat at both ends and only a few percent at one end: long contigs, but not yet whole chromosomes.

6 · Putting it together: the EBP standard

The Earth BioGenome Project (EBP) "Report on Assembly Standards" (version 7.0, January 2026) sets a minimum reference standard of 6.C.Q40 for eukaryotes with large genomes. The notation comes from the Vertebrate Genomes Project (Rhie et al. 2021), where the first number is log10 of the contig NG50 and the second log10 of the scaffold NG50; "C" in place of the second number means chromosome-scale scaffolds. Lesson 1 shows how to read it (lesson 1, The VGP route). The full EBP minimum:

criterionEBP minimummeasured with
contig N50≥ 1 Mb ("6")gfastats, QUAST
scaffoldschromosome-scale ("C"); > 90 % of sequence assigned to candidate chromosomesHi-C map (section 05)
base accuracy< 1 error per 10,000 bases (Q40)Merqury QV
false duplications< 5 %Merqury spectra-cn, purge_dups
k-mer completeness> 90 %Merqury
conserved genes> 90 % complete and single copy (e.g. BUSCO)BUSCO (section 10)
transcripts> 90 % of transcripts from the same organism mappableRNA-seq or Iso-Seq mapping
Simple explanation with examples: scoring our own assemblies
assembly contig N50 first no. scaffolds QV (method) verdict species B NG50 100s of kb 5 none below 40 (short reads, used in polishing) below 6.C.Q40 species C NG50 100s of kb 5 none lower still (same) below 6.C.Q40 species A primary N50 above 10 Mb 7 none above 50 (long reads: relative only) contig part met; no C; Q unknown

The log10 of a few hundred thousand lies between 5 and 6, so the first number for B and C is 5. Without scaffolds the second number equals the first, so neither has a "C". For species A the contig part (7 = at least 10 Mb) passes, BUSCO (above 95 %) passes, but there is no chromosome-scale scaffolding, and its QV cannot be stated honestly until short reads of the same animal are counted.

The lesson: one strong number (N50 above 10 Mb) does not make a reference genome. Each criterion needs its own evidence.

A minimal quality report

  1. Name the file
    Path, step (raw, polished, purged, scaffolded), and which product (primary, hap1, hap2). Check sequence names.
  2. Contiguity
    Total length, number of contigs and scaffolds, contig N50 and NG50 (state the expected size used), scaffold N50, number of gaps, largest sequence. gfastats or QUAST.
  3. Bases
    Merqury QV with the read type and k; say whether the reads were also used for polishing.
  4. k-mers
    k-mer completeness and the spectra-cn plot; false-duplication share.
  5. Genes
    BUSCO C [S, D], F, M with lineage and version (section 10).
  6. Reads back
    Mapping rate, depth distribution, flagged regions (Inspector, CRAQ or Flagger); Hi-C map if scaffolded.
  7. Contamination
    FCS-GX result (section 09).
