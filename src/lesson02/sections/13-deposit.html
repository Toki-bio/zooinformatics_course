13Depositing data: NCBI SRA and Genome, and where else to find genomes

An assembly is not finished until other people can find it. Journals ask for accession numbers before they accept a paper, and the next person who studies your species will first look in the public archives. This section shows what goes where, in what order, with which files, and how to search the archives for a genome that someone else has already made.

The three archives that share everything: INSDC

Three archives form the INSDC (International Nucleotide Sequence Database Collaboration): NCBI in the USA (its databases include GenBank and the SRA), ENA (the European Nucleotide Archive at EMBL-EBI, UK) and DDBJ (the DNA Data Bank of Japan). You submit to one of them. The record keeps the accession the first archive gave it and is also shown by the other two. The first letter of many accessions tells you where a record was submitted: S… or …N… for NCBI, E… for ENA, D… for DDBJ.

Each archive stores several kinds of record, linked to one another:

BioProject
The umbrella: what the study is about. NCBI accession PRJNA…, ENA PRJEB…, DDBJ PRJDB…. In the SRA the same study also has a "study" accession (SRP…/ERP…/DRP…).
BioSample
The biological material: one animal, or one tissue sample from it, with where and when it was collected. SAMN… (NCBI), SAMEA… (ENA), SAMD… (DDBJ); in the SRA also SRS…/ERS….
Experiment
One sequencing library on one instrument model (SRX…/ERX…/DRX…).
Run
The read files themselves (SRR…/ERR…/DRR…). This is the accession you download reads by.
Assembly
A genome assembly as a whole: GCA_ + 9 digits + version, for example GCA_123456789.1. GCA_ is the submitter's own record (GenBank/ENA/DDBJ); GCF_ is NCBI's RefSeq copy of a GCA assembly, always annotated, sometimes slightly changed by NCBI staff.
WGS set and sequences
The contigs, scaffolds and chromosomes of a WGS assembly get accessions that start with a 4- or 6-letter prefix, then a 2-digit assembly version, then a running number, for example ABCDEF000000000 in NCBI's guide. A record whose running number is all zeros stands for the whole set. Finished chromosomes in addition get ordinary GenBank accessions (two letters + six digits + version).
Decoder

What is this accession?

Type an accession from a paper, or pick an example. The page says what kind of record it is, which archive holds it, and lights up where it sits in the chain of linked records. Examples are the format examples printed in the archives' own documentation (ENA's accession guide, NCBI's WGS and Datasets guides, NGDC's guides); a few marked "synthetic" were made up to show a format and may not exist.

Simple explanation with examples: why so many numbers for one animal?

Think of a museum. The BioProject is the expedition ("Genome of the Russian desman"). The BioSample is the specimen in the drawer, with its label: species, sex, tissue, place, date, voucher number. Each sequencing library made from that specimen is an Experiment, and the files that came off the machine are Runs. The assembly is a reconstruction built from the runs, and its contigs are the individual pieces.

One animal sequenced with HiFi, Hi-C and Illumina, assembled into two haplotypes, gives roughly: 1 umbrella BioProject + 2 haplotype BioProjects, 1 BioSample (or 2–3 if the tissues were different samples), 3 Experiments, 3 or more Runs, 2 assemblies (2 GCA_ numbers), 2 WGS sets with thousands of contig accessions, and later perhaps 1 mitogenome record. A paper should cite the BioProject (it leads to everything else) and the GCA_ numbers.

Order of submission

  1. BioProject
    Describes the study. Register it first or let the SRA/Genome wizard create it. Projects with several haplotype assemblies need one BioProject per haplotype plus an umbrella BioProject that links them (NCBI staff create the umbrella if you do not have one).
  2. BioSample
    One record per sequenced individual. Both haplotypes of one animal share the same BioSample, which must have an isolate name to tell this animal from others of its species.
  3. SRA (reads)
    Raw reads with quality scores, linked to the project and sample. Do this before the genome: the assembly metadata refers to the reads, and an SRA submission done first gives you BioProject and BioSample accessions.
  4. Genome (WGS assembly)
    Contigs/scaffolds/chromosomes as FASTA (or .sqn if annotated), with assembly metadata. Mitogenome included here when it comes with the nuclear assembly.
  5. Later: annotation, updates
    Annotation can be added later as a new version. A corrected assembly is submitted as an update of the same GCA_ (the version number goes up).

SRA: the reads

The SRA wizard (submit.ncbi.nlm.nih.gov/subs/sra) goes: submitter → general info and release date → project → BioSample package → BioSample attributes → SRA metadata → files → review. The SRA metadata is a table with one row per experiment. Its controlled-vocabulary columns:

ColumnMeansTypical genome-project values
library_strategyWhat kind of experimentWGS for genomic reads, Hi-C, RNA-Seq
library_sourceWhat moleculeGENOMIC, TRANSCRIPTOMIC
library_selectionHow DNA was selectedRANDOM for shotgun libraries; size fractionation if fragments were size-selected; for Hi-C pick from the list (e.g. Restriction Digest, defined as "DNA fractionation using restriction enzymes")
library_layoutReads come in pairs or notpaired for Illumina pairs; single for HiFi/ONT
platform / instrument_modelThe machinePACBIO_SMRT: Sequel II, Sequel IIe, Revio, Vega…; OXFORD_NANOPORE: MinION, GridION, PromethION; DNBSEQ: DNBSEQ-G400, DNBSEQ-T7…; ILLUMINA: NovaSeq …; each platform also allows unspecified
filetype, filenameThe files of this rowfastq or bam; exact file names with extension
An instrument that is not in the list. The instrument list is fixed. In the ENA's copy of the shared INSDC schema (July 2026) there is no CycloneSEQ (section 1), for example, and its Oxford Nanopore list has only MinION, GridION and PromethION. Do not pick a different company's machine because the list forces a choice: readers will run the wrong error models on the reads. Write to the archive's help desk (NCBI: sra@ncbi.nlm.nih.gov) and ask which value to use, and state the real instrument, chemistry, flow cell and basecaller version in the library's design description and in the BioProject text.

Files. The SRA is a raw-data archive and wants per-base qualities. Accepted: FASTQ (gzip or bzip2 compressed; not zip), BAM (preferred by SRA; also unaligned BAM, as PacBio delivers HiFi), CRAM. SAM is not accepted. NCBI's format guide also lists PacBio bas.h5/bax.h5 (older PacBio instrument files) and ONT fast5 (basecalled, tarred) for "native" submissions; it does not mention pod5. Paired reads go as two files in matching order (not R1 and R2 concatenated into one). Limits: each FASTQ under 100 GB (split bigger files), at most 1,000 samples and 5 TB per submission. Assemblies are not accepted in the SRA.

Upload. Small sets: through the browser. Large sets: request a preload folder in the wizard, upload with FTP or Aspera into a new subfolder, wait 10–15 minutes, then pick that subfolder at the Files step. The account folder name (uploads/you@mail_xxxxx) and the Aspera key file are shown in the wizard.

# FTP (host, user name and password are shown in the SRA wizard)
ftp ftp-private.ncbi.nlm.nih.gov
  cd uploads/you@mail.org_xxxxx
  mkdir my_reads               # files must be in a subfolder, not the account folder itself
  cd my_reads
  binary
  mput *.fastq.gz

# Aspera command line (faster, resumes; needs the key file from the wizard)
ascp -i <key-file> -QT -l100m -k1 -d ./my_reads \
     subasp@upload.ncbi.nlm.nih.gov:uploads/you@mail.org_xxxxx/my_reads
# -k1 resume partial files; -l100m bandwidth cap (raise it if your link allows); -d create the folder
# Aspera needs TCP port 22 and UDP port 33001 open

Release date. The default is "release immediately following processing". You can set a later date (a hold until publication) and change it later; changing the SRA release date changes the project's and samples' dates too. Before contacting the help desk, quote your temporary submission ID (SUB…).

Genome: the assembly

The Genome Submission Portal (submit.ncbi.nlm.nih.gov/subs/genome) accepts either FASTA files (no annotation) or .sqn files (with annotation), never a mix. What NCBI checks, from its current submission guide:

  • Sequence names unique, under 50 characters, only letters, digits and - _ . : * #.
  • Length: contigs should be longer than 199 nt. No Ns at the start or end of any sequence (the validator calls it TerminalNs).
  • Gaps: a run of Ns inside a sequence is a gap, and contigs on both sides must be in the right order and orientation. Never join contigs of unknown order with Ns. You state the smallest N-run that counts as a gap (10 or less), how many Ns mean "gap of unknown length" (NCBI suggests 100), and the linkage evidence: what joined the two sides, e.g. paired-ends, proximity-ligation (Hi-C, section 5), map, align-genus.
  • AGP instead of Ns: scaffolds and chromosomes can also be described by an AGP file (9 tab-separated columns: object, start, end, part number, component type W for a contig or N/U for a gap, then contig name and coordinates, or gap length, gap type, linkage yes/no and evidence such as proximity_ligation). U gaps are always 100 long. YaHS writes this file for you (asm_scaffolds_final.agp, section 5).
  • Chromosomes: for a single genome the portal asks which sequences are chromosomes, plasmids or organelles; for batch and haplotype submissions put it in the FASTA header: >scaf1 [location=chromosome] [chromosome=1], >mito [location=mitochondrion] [topology=circular] [completeness=complete]. Chromosome names: up to 33 characters, no "chr" or "chromosome", not "Un" or "0"; linkage groups include "LG".
  • Contamination and adaptors: every genome is screened for foreign organisms and vector/adaptor sequence, and contamination is a common reason a submission comes back. NCBI recommends running its own FCS tools (section 9), FCS-adaptor and FCS-GX, on the final assembly before submitting, and removing or trimming what they flag.
  • Assembly metadata: assembly method (program name) and its version or date, estimated genome coverage (e.g. "40x"), sequencing technology (all of them), and whether the assembly is a full representation of the genome.

Two haplotypes. Choose the option "Pseudohaplotypes of a diploid/polyploid assembly". You must say how the assemblies relate: Principal/Alternate when one is clearly better (hifiasm's primary and alternate contigs), Haplotype 1/Haplotype 2 when they are of similar quality (hifiasm hap1/hap2), or Maternal/Paternal when parentage is known (trio data). One BioSample, one BioProject per haplotype, joined by an umbrella. Name them so they can be told apart, e.g. bSteHir1.pri/bSteHir1.alt or rPleGil1.0.hap1/.hap2 (NCBI's examples). The mitogenome goes into the principal (or maternal) assembly; NCBI's page gives no rule for a Haplotype 1/Haplotype 2 pair, so ask the help desk. See section 7 for what these products are.

Mitogenome alone. A mitochondrial genome without a nuclear assembly is not a Genome portal submission: it goes through the GenBank portal (SP-GenBank: eukaryote → "any other feature … organelle genomes"), as FASTA plus a feature table.

Annotation is optional. Without it, upload FASTA. With it, build a .sqn file with table2asn (NCBI's converter; it replaced tbl2asn). You need a template .sbt (made on NCBI's "Submission template" web form, it holds authors and contacts), the sequences .fsa, and features as a 5-column .tbl or NCBI-style GFF3. To submit an annotated genome, register BioProject and BioSample first and tick "autogenerate locus tag prefix".

# download: ftp.ncbi.nlm.nih.gov/asn1-converters/by_program/table2asn/ (rename to table2asn, chmod +x)
# genome with gaps: runs of ≥10 N are gaps, runs of exactly 100 N are unknown-length gaps, Hi-C evidence
# (illustration only: a contig assembly with no Ns and no Hi-C would leave the three gap options out)
table2asn -t template.sbt -indir fsa_dir/ -M n -Z \
          -gaps-min 10 -gaps-unknown 100 -l proximity-ligation \
          -j "[organism=Mus musculus] [isolate=MM-01]"
# one sequence + its feature table, with a GenBank flatfile to look at
table2asn -t template.sbt -i mito.fsa -f mito.tbl -V vb
# out: .sqn (submit this)  .val (validation messages)  .stats (summary of .val)
#      .dr (discrepancy report, from -Z)  .gbf (flatfile, from -V b)
# fix every ERROR/REJECT in .val and every FATAL in .dr before uploading

The 5-column feature table: a header line >Feature + the sequence ID exactly as in the FASTA, then one line per interval (start, stop, and the feature key on the first interval only), then qualifier lines starting with three empty columns. Minus-strand features are written with the larger number first. Columns are separated by TABs.

>Feature mito 5522 5572 CDS ← first interval carries the key 5706 6197 ← further intervals: start and stop only product Yip2p 4626 4590 tRNA ← minus strand: larger coordinate first 4570 4535 product tRNA-Phe

Example lines from NCBI's Feature Table page (a yeast CDS and tRNA). In the real file the gaps are single TAB characters.

Typical reasons a genome comes back: validation errors left unfixed (the .val/.dr files); contamination; a genome size far outside what GenBank has for the species; BioSample and assembly metadata that disagree; feature table IDs that do not match the FASTA IDs (the report then says NO_ANNOTATION). NCBI's pages give no fixed processing time: the status goes Queued → Processing (accessions assigned, staff review) → Processed (released). Unfixed errors cause the longest delays; if a genome is held until publication, tell NCBI at least two weeks before the paper appears.

    The European route: ENA and Webin-CLI

    ENA has the same objects (study PRJEB…, sample SAMEA…, runs ERR…). You register a Webin account, register the study and samples (web forms or spreadsheets), then send reads and assemblies with Webin-CLI, a Java program (Java 17 or newer; jar from github.com/enasequence/webin-cli/releases, or docker run enasequence/webin-cli, Docker). Each submission is described by a small text manifest; run with -validate first, then -submit. -test sends to a test server that archives nothing.

    Why some genomes are only there. Many Chinese groups (and some journals that publish their work) deposit in NGDC only. The 2021 GWH paper describes exchange with INSDC as limited to a test set (62 SARS-CoV-2 sequences shared with GenBank) and sharing of all public assemblies as a future plan. So an NCBI search that finds nothing does not mean your species has no genome: search NGDC separately.

    Searching and downloading. Search by species or accession at ngdc.cncb.ac.cn/gwh and ngdc.cncb.ac.cn/gsa (the site may first run a browser check, so scripted access to the HTML pages can fail; GWH has an API). Released assemblies download from download.cncb.ac.cn/gwh/ (FASTA, GFF3, TSV); released GSA runs from ftp://download.big.ac.cn/gsa3/<CRA>/<CRR>/. Controlled data in GSA-Human (and OMIX) need approval from a Data Access Committee first. Submitting to NGDC goes through BIG Sub (ngdc.cncb.ac.cn/gsub); files go by FTP to submit.big.ac.cn (run binary before mput) or by Aspera. GWH takes FASTA, annotation as GFF or TBL, AGP for chromosome-level assemblies and a CSV that assigns sequences to chromosomes.

    Simple explanation with examples: a checklist for "is there already a genome of my species?"
    1. NCBI Datasets: search the binomial, then the genus. Note GCA/GCF accession, assembly level (contig/scaffold/chromosome), contig N50, date, and whether it is a principal, alternate or haplotype assembly.
    2. Synonyms. Search old and new names: NCBI Taxonomy may still use a name your field has abandoned, or the reverse.
    3. NGDC GWH: same searches. A genome may be only here.
    4. GoaT: is someone already sequencing it? GoaT shows the sequencing status reported by projects affiliated with the Earth BioGenome Project. Write to them before you spend money.
    5. DNA Zoo and project portals (VGP/GenomeArk, DToL): sometimes released there earlier than in the archives.
    6. Reads without an assembly: search SRA/ENA/GSA for the species. Raw HiFi or Hi-C reads from someone else can sometimes be assembled or used for scaffolding (check the data's reuse terms).
    7. Literature: "Genus species genome assembly" in Google Scholar; check supplements on figshare/Zenodo/Dryad.
    8. Close relatives: if your species has nothing, the nearest relative's chromosome-level assembly still helps with scaffolding checks and BUSCO comparisons.

    Example: for the Russian desman Desmana moschata a search of the family finds the assembly of a relative, the Pyrenean desman Galemys pyrenaicus (GCA_019455555.1), onto which the published desman assembly was scaffolded; that is the kind of hit step 8 is about.

    In our projects
    • A mitogenome feature table that "had a bug". Our crayfish (Astacidae) mitogenome, 15,428 bp, was prepared for GenBank with table2asn (FASTA + 5-column .tbl + a .sbt template). The D-loop crosses the start of the circular sequence, so it was written as two intervals: 14919 15428 D-loop and then a bare 1 180. An automated review called the bare line a syntax error and the "final" file changed it to 1 180 D-loop. NCBI's Feature Table page shows the opposite: only the first interval carries the key, further intervals are start and stop only. The bare line was correct, and adding the key makes a second, separate D-loop feature. Lesson: check a "fix" against the format documentation and let table2asn … -V vb show you the flatfile before believing any reviewer, human or machine. The same package also added a missing trnL2 and shortened cox1 so it no longer ran into trnL2. (Sources: memory notes crayfish_mito_annotation_qc_2026-08-08 and crayfish_mito_final_resubmission_2026-08-09; NCBI feature_table page.)
    • An instrument that is not in the SRA list. The long reads of two of our unpublished small-mammal genomes (species B and C) were first described as Oxford Nanopore. The read IDs did not look like ONT IDs, and the provider confirmed a CycloneSEQ instrument and named the basecaller and its model. These reads must not be deposited as ONT "MinION/PromethION"; record the real instrument, flow cell, kit and basecaller as described above. (Source: our project notes.)
    • Which file is "primary"? For our species A (an unpublished rodent genome assembled with hifiasm), a file named hifiasm_primary.fa was a link to …_hifiasm.p_ctg.fa, which held hap1 (headers h1tg…): a script had picked bp.hap1.p_ctg.gfa with a wildcard (section 4, section 7), and for a while every number sent to collaborators came from hap1. The real primary (fewer contigs, about twice the contig N50, a clearly higher BUSCO C) is the better assembly. If such files go to NCBI as "Principal" and "Alternate", check names, contig counts and sizes against the assembler's own output files first. (Source: our project notes.)
