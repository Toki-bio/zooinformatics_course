01Pre-flight check: what lesson 1 must have told you

An assembler runs for one to several days and its output decides months of later work. Before starting it, write down about ten numbers from lesson 1. Each one points to a different tool, a different setting, or extra data you still need to order. If a number is missing or bad, it is cheaper to find out now than after a week of computing.

This section is the go/no-go list. For each item: where the number comes from, which values are fine, and what a bad value changes. Then a form where you type your own values and get a verdict with a suggested route. Then a table of what our own projects had at this point and what happened to them.

The items, one by one

  1. What machine made the reads

    Assemblers have a separate mode for each read type, and polishers use error models trained on one machine type. Do not trust file names. Look at the first line of the FASTQ file (the read name) and at the provider's run report: zcat reads.fq.gz | head -n 1. A read header that does not look like the machine you were told about is a reason to ask the provider before anything else.

    Decides: assembler mode (s04), polishing model (s06).

  2. Genome size, two ways

    The k-mer estimate (GenomeScope) and an independent figure: flow cytometry, a C-value database, or the assembly length of a close relative. k-mer estimates come out too small when high-copy repeats fall outside the fitted model, and twice too large or half too small when the model takes the wrong peak. When the two disagree by more than about 10 %, find out why before you go on (10 % is this course's rule of thumb, not a tool's threshold).

    The size is used later as the expected assembly length, as the divisor for coverage, for NG50, and for duplicate-removal cutoffs. Flye no longer needs --genome-size (optional since version 2.8) except together with --asm-coverage.

    GenomeScope 2.0 README · Flye USAGE.md, "Estimated genome size"

  3. Heterozygosity

    The share of positions where the two chromosome copies differ (GenomeScope's "het"). It decides whether the two copies of each region come out as one contig or as two.

    • Very low (around 0.1 % or less), or an inbred animal. A collapsed assembly is fine. Flye's FAQ says contiguity is not a problem at ~0.1 %. For inbred or homozygous genomes the README of hifiasm says to switch off its duplicate removal with -l0.
    • Typical diploid (a few tenths of a percent to about 1 %). hifiasm removes duplicates by itself. After Flye, expect to run purge_dups (s06).
    • High (above ~1.5 %, lesson 1's rule of thumb). The two copies separate into different contigs, so the primary assembly carries both copies of many regions. Flye's FAQ: it "will likely recover alternative haplotypes, but will not phase them", and contiguity drops. Plan duplicate removal, and Hi-C or parental reads for phasing (s07).

    purge_dups' own README warns of the opposite trap: in a species with low heterozygosity its automatic cutoffs can come out too high, so it removes too much and the assembly ends up smaller than expected. Check the cutoffs by eye.

    Flye FAQ.md "Are diploid genomes supported?" · hifiasm README · purge_dups README "Limitation"

  4. Ploidy

    How many copies of each chromosome a cell carries (from a chromosome count, or Smudgeplot). hifiasm's FAQ: its contig modules "are designed for diploid samples"; for polyploids only its unitig graphs are lossless. Flye always collapses copies into one. A triploid or tetraploid needs a specialised route that this lesson does not cover. GenomeScope 2.0 models up to hexaploid (6 copies).

    hifiasm docs faq.rst "Are polyploid genomes supported?" · GenomeScope 2.0 README

  5. Coverage, separately for each kind of data

    Total bases of that data type ÷ haploid genome size. Get total bases from seqkit stats -a -T (column sum_len), not from the order form. What the tools' own documents ask for:

    • Flye (any long reads): "satisfying assembly contiguity with 30x+ PacBio / ONT reads, if the read length is sufficient"; "you might have success with 20-30x"; "below 10x is not recommended".
    • hifiasm (HiFi): "Usually >=13x HiFi reads per haplotype", so at least ~26× for a diploid.
    • VGP (Galaxy training): "at least 30✕ PacBio HiFi coverage & around 60✕ Hi-C coverage" for diploids, and up to 60× HiFi for highly repetitive regions.
    • GenomeScope (short reads for profiling): "at least 15x coverage of the haploid genome", otherwise the fit is poor or does not converge.
    • Short-read assembly: ABySS's README gives its k advice for "2x150bp reads and 40x coverage".

    Flye FAQ.md "What is minimum read coverage" · hifiasm faq.rst · GTN VGP tutorial · GenomeScope 2.0 README · ABySS README

  6. Read length (long reads)

    Read N50 and N90 from NanoPlot or seqkit stats -a -N 50,90. A repeat longer than your reads cannot be crossed by any single read, so read length caps contig length. Flye "expects ... reads N90 over 1kb (5kb+ recommended)" and "will not work with reads shorter than 1kb"; it picks its minimum overlap from the read N90 (typically 3–10 kb). hifiasm in --ont mode drops reads shorter than 1,000 bases by default (--rl-cut).

    Flye FAQ.md, USAGE.md "Minimum overlap length" · hifiasm 0.25.0 CommandLines.cpp

  7. Read accuracy

    Usually given as a Phred Q value. It decides which assembler and which mode:

    • PacBio HiFi, under 1 % error (Q20 and better): hifiasm; Flye --pacbio-hifi.
    • ONT R10 reads: Flye --nano-hq ("Expected error rate is <3%"); hifiasm --ont (from version 0.21.0, "ONT simplex R10 reads", FASTQ only; it drops reads with a mean quality below Q10 by default, --sc-cut).
    • ONT R9 with Guppy5+: Flye --nano-hq --read-error 0.05 (under 5 % error).
    • Older ONT (R7 to early R9): Flye --nano-raw, 10–15 % error expected.

    Other nanopore-type machines (for example CycloneSEQ) are not named in these documents. Choose the mode by the measured error rate, and do not use a polishing or variant-calling model trained on a different machine.

    Flye USAGE.md "Supported Input Data" · hifiasm README, release 0.21.0 notes, CommandLines.cpp

  8. Foreign DNA

    An extra GC peak in the reads, or a k-mer bump at an odd coverage (lesson 1, step 5). Remove reads of a known contaminant before assembly, or remove contigs afterwards. Screen the finished assembly in any case (s09).

  9. Organelles

    Mitochondrial DNA is present in hundreds to thousands of copies per cell, so it shows as a thin k-mer tail at very high coverage. Assemblers build it as extra contigs, sometimes several genome lengths joined in a row, and nuclear copies of mitochondrial DNA (NUMTs) sit in the nuclear assembly. Plan to assemble it separately and to remove mitochondrial contigs from the nuclear set (s11).

  10. Repeat content

    GenomeScope reports the genome length and the unique length; the difference is the repeat share. With short reads, every repeat copy longer than about one read breaks the contigs (the k − 1 rule in s03), so a repeat-rich genome assembled from short reads gives short contigs whatever the coverage. Long reads that span the repeats are the only real fix.

  11. Extra data for chromosomes and haplotypes

    Hi-C reads, or short reads of both parents (trio). hifiasm's FAQ: with parental data its trio assemblies "should be always preferred", otherwise Hi-C mode is best; with long reads only, the haplotype sets are "not fully-phased". Without Hi-C (or a similar map) you get contigs, not chromosomes, and you cannot reach the "C" of the Earth BioGenome Project standard 6.C.Q40 (lesson 1; section 08). Order Hi-C now, from the same animal, while tissue is still available (s05, s07).

    hifiasm faq.rst "Which types of assemblies should I use?" · EBP assembly standards v7.0

Simple explanation with examples: why read accuracy decides so much

Q is just a short way to write an error rate. Q10 means 1 wrong base in 10, Q20 1 in 100, Q30 1 in 1,000. Every 10 points is ten times fewer errors.

Almost every assembly and profiling step works with k-mers (lesson 1). A k-mer is useful only if all of its k bases are right. With an error rate e, the chance that k bases in a row are all correct is (1 − e)k. For k = 21:

mean read quality errors per base 21-mers with no error Q10 1 in 10 11 % most k-mers are noise Q15 1 in 32 51 % Q20 1 in 100 81 % Q30 1 in 1,000 98 %

This is why GenomeScope wants "relatively low error" reads such as Illumina, and why an assembler must be told what kind of reads it gets: noisy reads have to be corrected or handled with looser matching before overlaps can be trusted.

A caution: "mean Q" is not computed the same way by every tool. seqkit's AvgQual converts each base's Q to an error probability, averages those, and converts back; averaging the Q numbers directly gives a higher, flattering value.

    Commands for the numbers you still miss

    # which machine? read names of the first 3 reads
zcat reads.fq.gz | awk 'NR%4==1' | head -n 3

# total bases (sum_len), read N50 and N90, Q20(%), Q30(%), AvgQual; -j = threads
seqkit stats -a -T -N 50,90 -j 8 reads.fq.gz > reads.stats.tsv

# coverage = total bases / haploid genome size (here 2.7 Gb)
awk -F'\t' 'NR==2{printf "%.1fx\n", $5/2.7e9}' reads.stats.tsv     # column 5 = sum_len

    seqkit 2.x, stats subcommand: -a all statistics, -T tab-separated, -N extra N-values. Check the column order in the header line of your version before relying on $5.

    In our projects
    • Check the machine from the reads. Species B and C files were called "ONT"; the read names start with a run ID, and the provider confirmed CycloneSEQ. Species A reads carry the run ID of a CycloneSEQ run report. The ONT models used later on these reads (Medaka, Clair3) are therefore questionable.
    • Compute coverage yourself. An early report gave the long-read coverage of B and C with no source, and both values were too high; read bases ÷ assembly length gave lower ones.
    • Know what a "size" file holds. The species A value passed to Flye was GenomeScope's unique length (about two thirds of the genome); harmless for Flye, which uses it only for coverage estimates, but it would be wrong as an NG50 ruler or for coverage.
    • k-mer sizes from long reads run low. Species A's size from long-read k-mers was a few percent below its Flye + Medaka assembly and below the published chromosome-level genome of a close relative.
    • A guess is not an estimate. Species B and C were started with a round "2g"; both assemblies came out about a fifth larger, and the guess was never checked against a published size.
