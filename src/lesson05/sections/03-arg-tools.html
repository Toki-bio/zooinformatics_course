03ARG tools: Relate, tsinfer, ARG-Needle, SINGER, ARGweaver

An ARG (s02) cannot be observed. It has to be inferred, and five programs do this in very different ways. This section says what each one reads, whether it needs phased haplotypes and known ancestral alleles, how many genomes it can take, and what comes out. The largest difference is at the end: some tools return one best answer, and others return a set of answers whose spread shows what the data cannot decide.

New words for this section

Phased
Each of an animal's two chromosome copies is known along its length (0|1 in a VCF, not 0/1; see lesson 4). All five programs work on single chromosome copies, called haplotypes. Only ARGweaver can work without phase, by averaging over the possibilities.
Ancestral allele
The base the common ancestor carried at a variable site. The other allele is derived. Deciding which is which is called polarising a site. It usually needs an estimated ancestral genome or one or more outgroup species.
Genetic map
A table of how recombination rate varies along a chromosome, usually in centimorgans (cM). 1 cM is a 1 % chance of a crossover per generation.
Tree sequence
A compact file of all local trees in which shared nodes and branches are stored once. It is the .trees format of the tskit library.
Threading
Adding one more haplotype to a partly built ARG by deciding, along the genome, where its lineage joins the existing trees. ARG-Needle, SINGER and ARGweaver all build ARGs this way.
Point estimate
One answer: one tree, one age. Its opposite here is a posterior sample: many answers drawn with a probability that reflects how well each fits the data and the model. Drawing them step by step is called MCMC (Markov chain Monte Carlo).

Simple explanation with examples: two ways to build an ARG

Copying. Relate and tsinfer ask, for each haplotype: "which others does this one look like here?" They use the Li and Stephens model, which describes a haplotype as a mosaic copied from other haplotypes, and a change of source as a recombination. Relate turns the copying into a tree at each position. tsinfer first builds likely ancestral haplotypes, then lets each one copy from older ones. Neither step dates anything: times are estimated afterwards from the mutations on each branch.

Threading. ARG-Needle, SINGER and ARGweaver start from a small ARG and add haplotypes one at a time, like adding a new specimen to a pedigree you have already drawn:

haplotype e, walking along the chromosome: positions 1-40 kb joins the branch above b, about 3,000 generations ago positions 40-55 kb joins the branch above d, about 9,000 generations ago <- a recombination at 40 kb positions 55-90 kb joins the branch above b again

ARG-Needle takes one good choice at each place and moves on. SINGER and ARGweaver draw the choice at random according to its probability, then remove pieces of the ARG and thread them again many times. That repetition is the MCMC, and it is why they are slower.

Relate

Relate (Speidel et al. 2019) first builds a tree at each position from the copying probabilities, then maps mutations onto the branches and estimates branch lengths with MCMC. Its add-on script alternates between estimating population size and re-estimating branch lengths, so size history comes out of the same run. Averaging coalescence rates within and between groups gives each population's size and cross-coalescence rate (the same idea as in lesson 4), and a further module tests for selection (s06). The authors expect it to "work equally well in other recombining species". Ancestral alleles must be set before the run, but a wrong one is not fatal: if a SNP fits the tree only with its alleles swapped, Relate flips it and records this in the is_flipped column of .mut.

# Relate v1.2.4. Filenames are given without extensions where the docs say so.
PATH_TO_RELATE/bin/RelateFileFormats --mode ConvertFromVcf \
    --haps data.haps --sample data.sample -i data_phased

# keep biallelic SNPs, flip so that 0 = ancestral, apply a mask of reliable bases
PATH_TO_RELATE/scripts/PrepareInputFiles/PrepareInputFiles.sh \
    --haps data.haps --sample data.sample \
    --ancestor ancestor.fa --mask mask.fa -o input

# -N is the size in HAPLOTYPES: twice the number of individuals
PATH_TO_RELATE/bin/Relate --mode All -m 1.25e-8 -N 30000 \
    --haps input.haps --sample input.sample --map genetic_map.txt \
    --dist input.dist --seed 1 -o run            # run.anc, run.mut

# size history: re-estimates branch lengths too. Set --years_per_gen: the default is 28, a human value
PATH_TO_RELATE/scripts/EstimatePopulationSize/EstimatePopulationSize.sh \
    -i run -m 1.25e-8 --poplabels data.poplabels --years_per_gen 1 --seed 1 -o popsize

# sampled branch lengths for one region; the topology stays fixed
PATH_TO_RELATE/scripts/SampleBranchLengths/SampleBranchLengths.sh \
    -i popsize -o region -m 1.25e-8 --coal popsize.coal --format a \
    --num_samples 100 --first_bp 100000 --last_bp 200000 --seed 1

The mutation rate here is the human value from the docs' example; use your species' rate per base per generation (lesson 4). In .mut, is_not_mapping = 1 means the SNP "could not be mapped to a unique branch". In the 1000 Genomes run, 86 % of SNPs mapped uniquely. RelateFileFormats --mode ConvertToTreeSequence writes a tskit file, but the docs warn that this gives no compression and loses how long branches persist.

tsinfer and tsdate

tsinfer (Kelleher et al. 2019) infers ancestral haplotypes from shared mutations, ordering them by allele frequency, and then finds a copying path for each ancestor and each sample. Its docs are clear about what comes out: "Internal node times are allele frequencies, not years or generations", and branch-length statistics raise an error until you date the result. tsdate (Wohns et al. 2022) does this from the mutations on each branch and works on any valid tree sequence. Its default method needs a mutation rate but no population size.

Where the data cannot settle a node, tsinfer leaves a polytomy: a node with more than two children. Its authors describe polytomies as a way of showing uncertainty, and the toy below shows why an honest "cannot say" can be worth more than a forced choice. tsinfer needs a known ancestral state for each site it infers from. Sites without one, as well as singletons and multiallelic sites, stay in the output with mutations placed by parsimony. Performance is "degraded" by genotyping error and "in particular" by phasing error.

# tsinfer 0.5.1, tsdate 0.2 (Python). Shell first: VCF to VCF Zarr. AA in the VCF becomes variant_AA.
#   vcf2zarr convert data.vcf.gz data.vcz
import tsinfer, tsdate

vdata = tsinfer.VariantData("data.vcz", ancestral_state="variant_AA")
ts = tsinfer.infer(vdata, num_threads=4)      # topology only

ts = tsdate.preprocess_ts(ts)                 # advised for real data
dated = tsdate.date(ts, mutation_rate=1e-8)   # per base per generation
dated.dump("data.dated.trees")

This is the interface of the released version. The development version (0.5.2) moves to a tsinfer run config.toml command, so check which version you installed. The tsinfer docs ran 5,000 simulated diploids in about 18 minutes and about 600 MiB. A "tsinfer-sparse" variant for array data appears in the ARG-Needle paper and is named, with ARG-Needle, as array-capable in the published review of Nielsen, Vaughn & Deng; its earlier author manuscript names only ARG-Needle. We could not find the variant in the tsinfer documentation (s04).

ARG-Needle, and what ASMC does in it

ARG-Needle (Zhang et al. 2023) was built for very large samples, including array data. Each new haplotype goes through three steps:

  1. Hashing. For each stretch of genome, find a short list of candidate close relatives by hashing genotypes. This avoids comparing it with everyone.
  2. ASMC. Estimate the age of the common ancestor (TMRCA) between the new haplotype and each candidate, along the genome.
  3. Threading. Attach the new haplotype to the closest candidate at each position, at the age ASMC gave.

ASMC (Palamara et al. 2018) is a hidden Markov model related to PSMC (lesson 4), but its input is a pair of haplotypes and it reports the TMRCA along the genome rather than a size history. It was designed so that the sparse, non-random SNPs of an array can be used: it models how those SNPs were chosen, which is the "A" (ascertained) in its name. So in ARG-Needle, ASMC supplies all the time information and the hashing only decides whom to compare. Three consequences follow from this.

  • The 300 floor. ASMC's model "requires at least 300 haploid samples", or 150 diploids. With fewer you get the CSFS requires 300, where CSFS is the conditional site frequency spectrum.
  • A built-in demography. ASMC needs a precomputed .decodingQuantities.gz file holding the demographic model, mutation rate and allele frequencies, and the final ARG normalization (which adjusts node times to match a stated size history) uses a demography too. The default for both is a European human model. For another species you must supply your own, computed with the PrepareDecoding tool from a size history you already have, for example from PSMC. Population sizes in these files are haploid.
  • ASMC-clust. The same package can run ASMC on all pairs and cluster the pairwise ages into a tree at each site (--asmc_clust 1). This scales with the square of the sample size, so ARG-Needle itself is the one for big samples.
# arg-needle 1.1.0 (pip install arg-needle). Requires 300 or more haplotypes.
arg_needle --hap_gz data.haps.gz --map data.map --mode sequence \
    --asmc_decoding_file my.decodingQuantities.gz \
    --normalize_demography my.demo \
    --out data                                   # data.argn

arg2tskit --arg_path data.argn --ts_path data.trees

The map has four columns (chromosome, SNP name, genetic position in cM, physical position in bp), and both positions must increase strictly. The manual warns that the parameters were "optimized for use with SNP data, so it may be slow when applied to sequencing data". ASMC's paper adds that pairs across individuals need "haplotypes phased with extremely high accuracy". The SINGER paper notes that ARG-Needle "does not map mutations to branches"; arg-needle-lib has its own functions for mutations on an ARG. Array data get their own section (s04).

SINGER

SINGER (Deng, Nielsen & Song 2025) threads haplotypes in two cheaper steps, first which branch and then what time, and explores the space of ARGs with MCMC that changes both topology and times. Its HMMs assume a constant size, but a rescaling step then stretches and shrinks time so that mutation counts match branch lengths. In the authors' simulations this made it robust to size changes, and it needs no size history from you. The limits come from the paper and README: phased, contemporary, whole-genome data; polymorphic sites with missing data are excluded; and the model assumes infinite sites, "which may not be applicable to cross-species data". The authors say directly that good phasing is "often challenging, especially for ancient DNA and non-model organisms".

# SINGER beta. -vcf and -output take PREFIXES: -vcf chr1 reads chr1.vcf (the most common bug, says the README).
# Choose m first, then Ne from pi = 4 * Ne * m. Here -Ne is DIPLOID. Use -polar 0.99 for polarised data.
singer_master -m 1.25e-8 -Ne 10000 -ratio 1 -polar 0.99 \
    -vcf chr1 -output chr1_w0 -start 0 -end 5e6 -n 100 -thin 20

# long chromosomes: run windows of about 5 Mb, then join with merge_ARG.py
python merge_ARG.py --file_table sub_file_table --output merged_ARG

# each sampled ARG is 4 text files (nodes, branches, muts, recombs): make .trees files
convert_to_tskit -input chr1_w0 -output chr1_w0 -start 0 -end 100 -step 1

# check convergence before trusting anything
python compute_traces.py -prefix chr1_w0 -m 1.25e-8 \
    -start_index 0 -end_index 100 -output_filename chr1_w0.traces

Defaults from the README: -n 100 samples, -thin 20 iterations between them, -ratio (recombination over mutation rate) 1, -polar 0.5 for unpolarised data. The README advises: "only using one single sample is NOT ideal". Regions with little data, such as centromeres, cause the second most common failure. Skip them: windows need not be adjacent. Branch lengths are in generations. The software still calls itself a beta version.

ARGweaver and ARGweaver-D

ARGweaver (Rasmussen et al. 2014) showed that sampling ARGs at genome scale is possible. It works in fixed, discrete time steps, and its sites model allows the same site to mutate more than once (Jukes-Cantor). The manual asks for no ancestral allele. It accepts unphased data through --unphased, which "will integrate over phasings"; the SINGER README agrees that ARGweaver "has better support" for missing and unphased data. ARGweaver-D (Hubisz et al. 2020) adds a user-defined demographic model with population splits and migration, and can give the probability that a region was introgressed. Its manual was last updated in 2013, and the last commit is from 2023.

# ARGweaver (README example values, human-like). -c 10 compresses the alignment into 10-bp blocks.
# -N is diploid. -n is iterations (default 1000); a sample is written every 10 (--sample-step).
arg-sample -s data.sites -N 10000 -r 1.6e-8 -m 1.8e-8 \
    --ntimes 20 --maxtime 200e3 -c 10 -n 100 -o run/out

# TMRCA along the region, across the sampled ARGs
arg-extract-tmrca run/out.%d.smc.gz > run.tmrca.txt

Time spent before the chain settles must be discarded (burn-in). The ARGweaver paper used 500 burn-in iterations in simulations, then 1,000 sampling iterations keeping every tenth, and for its 54 human genomes 2,000 iterations per block of about 2 Mb. Those figures are one study's settings, not defaults.

One best tree or a set of trees

Why would a best tree not be enough? Nielsen and colleagues give the reason: in humans the mutation and recombination rates are "fairly similar, meaning that, on average, every time a new mutation occurs that might provide information about the tree structure, a new recombination event will also occur". So any one local tree is supported by very few SNPs. A method that returns one tree still draws it just as cleanly. Treating that tree as true, the review warns, induces "false certainty in the results of any analysis".

The tools fall into three groups (Table 1 of the review):

  • One ARG: tsinfer and ARG-Needle. tsdate does add a variance to each node time, but on a fixed topology.
  • One topology, sampled times: Relate, through SampleBranchLengths.
  • Sampled topologies and times: SINGER and ARGweaver.

The difference shows in a measurable way. If a 90 % interval is honest, it should contain the truth 90 % of the time. On simulations in the SINGER paper, it did so 85 % of the time for SINGER, 54 % for ARGweaver and 44 % for Relate, for pairwise coalescence times. The authors attribute Relate's low figure to sampling times under a fixed topology. That is the authors' own benchmark, and the review, which shares authors with it, also places SINGER first on accuracy. Sampling is not free either: the sampled tools are limited to hundreds of genomes at most.

What one best tree hides

Four haplotypes, a to d, share one local tree on a stretch of genome. The toy simulates a true tree and its mutations (N = 10,000, μ = 1.25 × 10−8, constant size, no recombination inside the stretch), then computes the probability of every tree and set of times given those SNPs. The SNP table has one column per SNP, and 1 is the derived allele. Real tools have to approximate this calculation; with four haplotypes a fine grid is close to exact. Control. The same code was tested outside the page. With no SNPs it matches the closed-form answer, and with SNPs it matches an independent simulation. On 1,500 simulated data sets at each of 1, 3 and 10 kb, the 90 % interval for a and b held the truth in 91 %, 89 % and 91 % of cases when trees and times were sampled, but in 72 %, 78 % and 88 % when the best tree was fixed. The best tree was the true one in 29 %, 48 % and 70 % of cases, close to its stated probability. These toy figures show the direction of the effect; they are not the published ones.

Time units for tsdate come from mutation_rate being per generation, and for ARG-Needle from its generation-based demography; that reading is ours, not a sentence in their docs.

All five need good haplotypes, and this hits zoologists hardest. Relate's authors warn that computational phasing can inflate recent population size, tsinfer degrades with phasing error, and pairs in ASMC need very accurate phase. Many wild species also have no genetic map, which Relate and ARG-Needle require. A flat map at an assumed rate will run, but that is our suggestion, not a documented recipe, and recombination hotspots will then be missed. For polarising, Relate and tsinfer depend on a good ancestral genome, and SINGER's authors note that polarising is difficult where polymorphism is shared across species.

Which one to try

Our reading of the documents above, not a rule from any of them.

  • Tens of phased genomes and a question about one region: SINGER, because you need the intervals.
  • Few genomes without reliable phase, or a known demographic model and a question about introgression: ARGweaver or ARGweaver-D, on short regions.
  • Hundreds to a few thousand phased genomes and a question about size, splits or selection: Relate. Add SampleBranchLengths for loci you plan to interpret.
  • Very large samples, or one compact file for many analyses: tsinfer + tsdate.
  • Array data or biobank scale, with at least 300 haplotypes: ARG-Needle, after reading s04.

One or two genomes per species belong with the methods of lesson 4. What these tools then give you is the subject of the next sections: s05 for recent shared segments, s06 for selection, and s08 for what happened when a real cohort was run through this kind of pipeline.
