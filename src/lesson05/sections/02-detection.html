02How long reads see methylation

A methyl group on a cytosine does not change the letter: a 5mC is still read as C. So a machine that reports only letters cannot see it. Short-read methods solve this with chemistry before sequencing. Long-read machines measure a physical signal while they read each native DNA molecule, and the methyl group nudges that signal. Whether you can ever get methylation out of your data therefore depends on one practical question: did the signal, or a call made from it, survive into the files you received?

Four ways to see a methyl group

The two long-read platforms most used for methylation measure different things. Bisulfite and EM-seq are the short-read reference methods; they are listed only for comparison (section 07 returns to them as a check).

In vertebrate genomes methylation is found mainly at the C of CpG sites (section 01), and the standard long-read models for vertebrates look at CpGs. For the instruments themselves see lesson 2, section 04.

Nanopore: the current changes at a methylated base

In a nanopore sequencer a protein pore sits in a membrane with a voltage across it. Ions flowing through the pore make a tiny current. A motor protein feeds one DNA strand through the pore, a base at a time. Several neighbouring bases sit in the narrow part of the pore together, so the current at each step depends on a short word of bases, a k-mer, not on a single base. The basecaller turns this staircase of current levels into letters. A methyl group on a C changes the shape and charge inside the pore a little, so every step whose k-mer contains that C sits at a slightly different level. The early methods (Simpson et al. 2017, Rand et al. 2017) showed this with DNA methylated in the test tube; today's models are neural networks trained the same way, on DNA of known methylation.

PacBio sees the same methyl group in a different way. The polymerase builds a new strand on the template and each added base gives a flash of light. The IPD is the pause before a base is added and the pulse width is how long the addition takes (PacBio BAM specification). A modified base in the template changes these times around it.

One molecule, with and without a methyl group

A toy 12-base stretch with one CpG. In nanopore mode each step is the current of one 5-base word in the pore; in PacBio mode each bar is one added base and the gap before it is the IPD. All levels, shifts and times are invented to show the principle; real k-mer sizes, levels and shifts depend on the pore, chemistry and model. Switch the methyl group on, then raise the noise.

A real model does not look at one step. It takes the signal over a window of bases around each candidate site and outputs a probability that the C is modified. Because the shift is small next to the noise, the answer for a single read is a probability, not a yes or no; certainty comes from many reads at the same site (section 03).

Three things to take from the toy. With good separation almost any threshold near 0.5 works. With poor separation, a low threshold produces false methylated calls and a high one misses real ones, so the site's estimated level is pulled towards whichever error dominates. And the threshold is a choice made after calling: Dorado writes the probability itself, and its --modified-bases-threshold only decides which low-probability calls are written to the file (its help text says this applies to all-context models); it "has no effect on the modification probabilities" (Dorado documentation). Calling modified bases with Dorado

For Oxford Nanopore data the basecaller is Dorado (version 2.1.2, 26 August 2026). Modified bases are called during basecalling, from the raw signal: you add a modification model to the basecalling model. Dorado reads only pod5 input; fast5 support was removed in version 1.0.0 (May 2025), and fast5 files must first be converted to pod5. In the source code the modification caller takes chunks of signal, not letters, which is why a FASTQ file cannot be re-called for methylation.

# basecall + 5mC/5hmC at CpG sites, from raw signal (pod5), on a GPU; output: unaligned BAM with MM/ML tags
dorado basecaller sup,5mCG_5hmCG pod5s/ > calls.bam

# the same, pinning the basecalling model version (the modification model then matches it)
dorado basecaller sup@v5.2.0,5mCG_5hmCG pod5s/ > calls.bam

# add the move table (signal-to-base map) if other tools will need it later
dorado basecaller sup,5mCG_5hmCG --emit-moves pod5s/ > calls.bam

The first argument is a model complex: a speed (fast, hac or sup, from fastest to most accurate), an optional @version, then modification models separated by commas. Modification models are tied to the basecalling model version, and only one modification model per base type is allowed (so sup,4mC_5mC,5mC_5hmC is refused: both act on C). For the current R10.4.1 DNA sup@v5.2.0 model, the documented modification models are:

Model nameWhat it callsWhere

For a vertebrate genome, 5mCG_5hmCG is the usual choice. The output is an unaligned BAM: one record per read with the letters, qualities and the modification calls in two tags, MM and ML. The BAM header line @RG records the basecalling model and the modification model names. Dorado refuses to combine FASTQ output with modification models; its own error message reads "--emit-fastq cannot be used with modbase models as FASTQ cannot store modbase results."

PacBio: calls made on the instrument

For HiFi reads, the ccs step, run with --hifi-kinetics, stores averaged timing values for each strand of the molecule separately as per-base tags (fi/fp for the forward strand, ri/rp for the reverse). PacBio's jasmine (version 26.1.3) then turns them into calls:

  • 5mC at CpG sites: one call per CpG pair, written on the forward strand, using timing from both strands; if either strand's timing is missing, no 5mC calls are made for that read. Reads with fewer than 2 passes (--min-passes) get no calls.
  • 5hmC at CpG sites (strand by strand) and 6mA (for the Fiber-seq assay) with separate models.
  • Output: the same MM/ML tags as Dorado.

PacBio's Revio page states that "every standard run delivers on-instrument 5mC, 5hmC, and 6mA methylation calling". So a modern HiFi delivery in BAM form normally already carries the calls; the timing values themselves may or may not be kept in the delivered file. For counting calls per CpG, jasmine's README now recommends PacBio's MethBat and calls the older pb-CpG-tools deprecated (section 03).

How the calls are written: MM and ML tags

Both platforms use the same two tags, defined in the SAM tags specification (hts-specs). MM says which bases were assessed and ML gives a probability for each. A tag such as MM:Z:C+m?,3,1; reads: base C, on the same strand as the read (+), modification m (5mC), then a list of how many Cs to skip before each called C. ML:B:C,249,4 then gives one number from 0 to 255 per called C; the number N means a probability between N/256 and (N+1)/256. The flag after the code says what the skipped Cs mean: . (or nothing) "assume unmodified", ? "not assessed, no information". Positions count from the 5′ end of the read as it was sequenced, so the tags do not change when an aligner flips a read to the reverse strand.

Simple explanation with examples: bold letters in a retyped letter

Think of a hand-written letter in which some words are underlined. The underlining is the methylation; the words are the DNA letters. A nanopore or PacBio machine "reads the paper": it can feel the underlining. A basecaller that only outputs letters is a typist who retypes the letter in plain text. The words survive, the underlining is gone, and no amount of rereading the typed copy brings it back.

paper (signal): the CG site in this CG island typed (FASTQ): the CG site in this CG island underlining lost typed + notes: the CG site in this CG island MM:Z:C+m?,0,1; ML:B:C,240,20 "first C: 94 % underlined; third C: 8 %"

The MM/ML tags are the typist's notes in the margin: "the first C was underlined, quite sure; the third C probably not". A FASTQ file has no margin. To get the notes, either keep the paper (the raw signal, pod5) so the letter can be read again with a better typist, or ask the typist to write the notes the first time (basecalling with a modification model, delivered as BAM).

Bisulfite is a different trick: before typing, you rub the paper with a chemical that turns every non-underlined C into a T. Now the plain typed copy shows methylation as letters, and a plain FASTQ is enough. That is why short-read methylation data can be FASTQ, while long-read methylation data cannot.

Why a plain FASTQ loses the information

A FASTQ record holds four things: a name, the letters, a separator and one quality character per letter (see lesson 1). There is no field for a probability per base of being modified, and the raw signal is not stored at all. Once reads are delivered only as FASTQ, methylation cannot be recovered from them: there is nothing to re-call. (Methylation can still leave faint traces as extra basecalling errors at modified sites, which can look like SNPs; section 07 covers this. That is a nuisance, not a measurement.)

Explain

What can I still do with the files I received?

Pick what your provider delivered. The answers follow the Dorado and jasmine documentation; for CycloneSEQ they reflect what we could and could not find.

CycloneSEQ

CycloneSEQ (MGI) is a nanopore platform with its own pore, chemistry and basecaller, and Dorado's model list covers only Oxford Nanopore pores and chemistries. We could not find vendor documentation that describes a modified-base caller or MM/ML output for CycloneSEQ, and an independent first look at CycloneSEQ data (Wick 2024) found the basecalling software not freely available. A 2026 preprint (Liu et al., not peer-reviewed) compared bacterial DNA with and without its natural methylation on CycloneSEQ and ONT: methylated motifs raised substitution errors on both platforms. The authors also tested two research methods that align the raw CycloneSEQ current to a reference and detected a difference at one known methylated bacterial motif; both need the raw signal, and neither is a vendor tool that writes MM/ML tags. So methylation does affect CycloneSEQ reads, but we found no documented, ready-made way to turn it into per-base methylation calls. If your provider offers one, ask for its name, version and output format; until then, treat CycloneSEQ FASTQ as carrying no methylation information.

What to ask your sequencing provider to keep

Ask for this before sequencing: none of it is part of a plain FASTQ delivery, and a provider cannot send what it did not keep. A checklist, written from the request our lab sent:

  1. The raw signal
    pod5 (or fast5) for every run. It is large (by our rough estimate, roughly ten times the size of the reads themselves), but it is the only thing that allows re-calling with newer models.
  2. Was a modification model used?
    If yes, the BAM files with MM/ML tags. If no, ask for a re-call with a CpG model (for ONT: sup + 5mCG_5hmCG, with --emit-moves), delivered as unaligned BAM. For PacBio: the HiFi BAM with MM/ML tags, not a FASTQ export.
  3. Run details
    Instrument, flow cell, library kit, basecaller name, model name and version, read filtering, number of flow cells or runs. Without the model name nobody can judge the calls later.
  4. Run reports
    The sequencing summary and run reports.
In our projects: the reads of species A arrived without methylation. Our long reads of species A (a rodent) were delivered as a single FASTQ. Their headers are not in Dorado style and carry no basecaller model or read-group tags, and we received no pod5. So the lab's plan, to re-basecall with sup, --emit-moves and the 5mCG_5hmCG model and get CpG methylation "for free" with modkit pileup, could not run (and our server has no GPU for it). The checklist above is the request we then sent to the provider; no answer about methylation is recorded in our notes. The read-ID style suggests the reads are CycloneSEQ, not ONT, which would rule out Dorado anyway; for two other small mammals (species B and C) the provider confirmed a CycloneSEQ instrument and named a basecall model whose name (our reading) contains no modification model. For the lizard Darevskia armeniaca, our sequencing sheet lists a PacBio HiFi run in a folder labelled "_met", but the read file listed is a FASTQ; we have not checked what the original BAM contained.
