04Distance trees: UPGMA and neighbour joining

Section 03 turned a pair of sequences into one number, the distance between them. This section builds a tree from a table of such numbers. Two methods do it: UPGMA, which is simple and assumes every lineage changes at the same speed, and neighbour joining, which does not need that assumption. You will run both, step by step, on the same small table, and then make one lineage evolve faster and watch one of them fail.

What a distance method does

A distance matrix is a table with one number for every pair of tips: how different those two sequences are. A distance method uses only this table. It never looks at the sequences again. It repeats one move: find the pair that should be neighbours, replace the pair by one new group, and shrink the table by one row. When one group is left, the tree is finished. This is quick, and it is easy to follow by hand. The two methods differ in one thing only: what "should be neighbours" means.

Words used below. A cluster is a tip or a group of tips treated as one item. A branch length is the amount of change along a branch, in the same units as the table. The topology is the branching pattern alone, without lengths.

UPGMA: join the closest pair, always

The name is "unweighted pair group method with arithmetic mean". It is the method of Sokal and Michener (1958). The steps:

  1. Find the smallest number in the table. Join those two clusters.
  2. Put the new node halfway: its height is half the distance. Each of the two new branches reaches from the new node down to its cluster's own height (a tip has height 0).
  3. Make a smaller table. The distance from the new cluster to any other cluster is the average of all tip-to-tip distances between them. This is the formula of the average method in SciPy, which its documentation calls "the UPGMA algorithm".
  4. Repeat until one cluster is left. That cluster is the root.

The tree it draws has every tip at the same distance from the root. The word for this is ultrametric. That is a built-in assumption: UPGMA gives the correct tree only if all lineages changed at the same rate, a molecular clock (s09). Then distance grows with time since the split, so the smallest distance is the youngest split, and joining the closest pair is right. If one lineage changes faster, it is far from everyone, even from its own sister, and the closest pair in the table may not be the closest relatives.

Neighbour joining: join the pair that is close compared with everything else

Saitou and Nei (1987) proposed it. The abstract says: "The principle of this method is to find pairs of operational taxonomic units (OTUs [= neighbors]) that minimize the total branch length at each stage of clustering of OTUs starting with a starlike tree." A starlike tree has all tips joined to one central point and nothing else. Each step pulls one pair out of the star, choosing the pair that keeps the total length of the tree smallest. The formulas below are as written in the code comments of the scikit-bio implementation, which cites that paper. With n clusters left:

Row sum r
For each cluster i, add up its distances to all the other clusters: ri. A cluster on a long branch has a large r.
Q criterion
Q(i,j) = (n − 2) × d(i,j) − ri − rj. Join the pair with the smallest Q. A pair scores well if it is close to each other and each of the two is far from everything else.
Branch lengths
Li = d(i,j)/2 + (ri − rj)/(2(n − 2)), and Lj = d(i,j) − Li. The two branches are not equal: the cluster with the larger row sum gets the longer branch.
New table
d(new,k) = (d(i,k) + d(j,k) − d(i,j))/2 for every other cluster k.
The end
When three clusters are left, their three branch lengths follow from the three distances: the branch to a is (d(a,b) + d(a,c) − d(b,c))/2, and likewise for the others.

The result is an unrooted tree: it has no root and no time direction, and its tips are not all the same distance from the centre (s01). To root it you add an outgroup or use the midpoint of the longest path, as s01 explains. In the figures below an unrooted tree is drawn from an inner node, only so that it fits on the page.

Why does this work when rates differ? Take a tip on a long branch. All its distances are large, so its row sum r is large, and Q subtracts that. The long branch no longer makes the pair look unrelated. NJ compares each pair with the whole row of distances, not with the single smallest number.

The test case for NJ is the additive distance matrix: the distance between two tips equals the sum of the branch lengths on the path between them in some tree. If the table is additive, NJ gives back that tree. The scikit-bio documentation says "NJ is most accurate when distances are additive", and the check at the end of this section confirms exact recovery on 200 random additive tables. Real tables are not exactly additive, because distances are estimated from finite sequences (s03). The same documentation warns that then "negative branch lengths may be produced". In that implementation NJ takes time proportional to n3 for n tips.

Try the slider at 4 or above and press To the end. UPGMA first joins tips 4 and 5, as it should. Then the smallest distance in its table is between tips 2 and 3, not between tips 1 and 2, because tip 1 is now so far from everyone. At speed 3 the two distances are equal and the program takes the first one it finds. Neighbour joining gets the true tree at every speed, because its Q values cancel a long branch.

Two things this toy does not show. The toy table is exact; real tables carry noise, so NJ's answer is then only an estimate and can be wrong. And both methods give one tree with no measure of how far to trust it: that needs s07. Methods that score whole trees against the sequences come next, in s05 and s06.

Simple explanation with examples: why the closest pair can be the wrong pair

Think of a family. Anna and her brother Ben grew up in the same town. Ben still lives there, and so does their cousin Carl, in the next street. Anna emigrated and now lives 9,000 km away. Measure only how far apart people live: Ben and Carl are closest, and "join the closest pair" says Ben and Carl are the nearest relatives. But Anna and Ben are siblings. Distance travelled is not the same as kinship.

DNA does the same. If Anna's lineage changed fast, its sequence is far from everyone, including its sister lineage. UPGMA reads the table like a map of distances and trusts the smallest number, so it pairs the wrong two. Neighbour joining asks: "who is close, once I allow for who is far from everybody?" Anna is far from everybody, so her large distances are discounted, and her best partner, Ben, is found.
