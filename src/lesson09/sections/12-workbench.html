12One alignment, every method

The earlier sections each used their own toy. Here one small alignment goes through all of them. You can follow every number from the columns to the finished tree, then see exactly how each support value on a branch is calculated.

Five tips is the smallest size that still shows everything. It has only 15 possible unrooted trees, so instead of a tree search the toy simply scores all 15, and nothing is hidden. Each ready-made alignment was simulated on the same known tree, so here, unlike in real work, you can check who was right. Click any base to change it, and all the trees and numbers are worked out again.

Simple explanation with examples: what differs between the methods

All five methods read the same 20 columns, and they differ in what they do with them.

  • UPGMA and neighbour joining first squeeze the columns into one table of distances, then join tips by a fixed recipe. They never compare whole trees. See section 04.
  • Parsimony keeps the columns, and scores each tree by the fewest changes needed. See section 05.
  • Maximum likelihood keeps the columns too, and scores each tree by the probability of the columns under a model of change. See section 06.
  • Bayesian inference uses the same probability, adds a prior, and reports how much time a random walk spends at each tree. See section 08.

Example: two tips that both changed a lot may share a base by chance. A distance table cannot tell why they look alike. Parsimony counts it as a shared change. Likelihood knows that long branches make chance matches more probable, and allows for it.

Things to try

  1. One fast lineage. Step through UPGMA, then neighbour joining. Compare the first join each makes, and read in the Q table why they differ.
  2. Two long branches. Open Parsimony and find the columns where A and C share a base. On the true tree such a column usually costs an extra step. Then open Maximum likelihood and see the same tree win or lose by how little.
  3. Any preset. Change one base in an informative column and watch which methods change their minds. With 20 columns, one base can be enough.
  4. Bayesian. Press 1 step a few times and read the arithmetic, then run 10,000 steps. On weak data the bars spread over several trees, which is the honest result.

What this toy leaves out

  • Twenty columns is far too few for real work. Everything here is noisy on purpose, so that you can see the noise. The rules of thumb in section 07 were not made for alignments this small.
  • The only model is Jukes-Cantor (section 03), and the simulated data obey it. On real data the model is an assumption, and a wrong one can give high support to a wrong branch.
  • Real programs cannot score every tree. They search, and can miss the best one.
  • IQ-TREE re-fits the five branches around a rearrangement in one pass by default, while this toy repeats until they settle. SH-aLRT values can therefore differ somewhat on data like these. With the pass count raised, IQ-TREE and this toy gave the same values, apart from resampling noise, wherever their likelihoods matched.
  • The Bayesian prior here is one simple choice. With so few columns it matters: an exponential prior with mean 0.1 pulls against long branches.
