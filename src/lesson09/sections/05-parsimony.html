05Parsimony

The distance methods of the last section first squeeze the sequences into a table of distances and then build a tree from the table. Parsimony does not make a table. It looks at the sequences column by column and asks one question of every possible tree: how many changes would this tree need to explain what we see? The tree that needs the fewest is the winner. The idea is old, simple and easy to do by hand, and its failure is also instructive. This section shows how the changes are counted, which columns carry information, how the method is misled when some branches are long, and why a SINE insertion is a particularly clean kind of character.

The criterion

A character is one column of the alignment. In each taxon (a species or sequence in the tree) the character shows one state. A tree explains a character if we can write a state on every inside node of the tree so that the states change as rarely as possible along the branches. Each change is one step. The parsimony score of a tree is the number of steps summed over all characters. Among the trees that were tried, maximum parsimony picks the lowest score. "Parsimony" means thrift: the tree that needs the fewest changes is the one that assumes the least.

Notice what is missing. There is no model of how fast each base changes, and branch lengths play no part in the count. That keeps the method simple, and it is also where it goes wrong later in this section. Compare the model-based methods in section 06.

Counting the steps on one tree: Fitch's method

For one character on one tree there could be very many ways to write states on the inside nodes. Fitch (1971) gave a method that finds the smallest number of changes without trying them all. Start at the tips. Every tip has a set holding its one state. Then move toward the root, taking two sister nodes at a time:

if the two sets share a state:  parent set = the shared states  (no step)
otherwise:  parent set = both sets together  (add one step)

The number of "otherwise" cases is the score for that character. The page below applies this rule to a 5-taxon tree. Click a letter on the tree, or in the table, to change a state. Red dots mark the nodes where a step was added.

Which sites matter

Look at the table's "kind of site" column and try changing bases.

  • A constant site has the same state everywhere. It needs no change on any tree.
  • A site where every state except one is shared by only one taxon (for example A A A A T) is uninformative. That single odd taxon needs exactly one change wherever it is placed, so every tree costs the same.
  • A site is informative when at least two different states each occur in at least two taxa (G G A A A). Only such a site can prefer one tree over another.

"Informative" means only that the site could prefer some tree. A site can be informative in general and still cost the same on the three trees shown, as site 8 does here. Parsimony therefore ignores most of an alignment: only the informative sites vote. When the species are close relatives, most columns are constant, and a few informative ones decide the tree.

Counting steps for one tree is easy. Finding the best tree is not: the number of possible trees grows very fast with the number of taxa (see section 01), so programs search through trees rather than test them all. Searching is the same problem for every tree method, and section 06 comes back to it.

When parsimony is misled: long branches

Parsimony counts every change as evidence. Think about two lineages that have changed a great deal, so that their branches in the tree are long. Each has many changes of its own. Because there are only four bases, some of these changes will by chance land on the same base in both lineages. To the counting method, a base shared by two taxa looks like a base inherited from a common ancestor, and the two long branches are pulled together, even when they are not close relatives. This is long-branch attraction.

Felsenstein (1978) showed this in a four-taxon case. His abstract says that for the three parsimony and compatibility methods he studied, the conditions of failure "are essentially that parallel changes exceed informative, nonparallel changes", that this is possible "even when change is improbable a priori, provided that evolutionary rates in different lineages are sufficiently unequal", and that the methods "will fail to converge to the true phylogeny as more and more data are accumulated". (We read the abstract only; the paper itself was not available to us.) The last point matters most: more data does not rescue the method, because the extra data carry the same wrong signal.

Simple explanation with examples: why a shared base does not always mean shared ancestry

Imagine two cousins, each given a different number at birth, who both change their phone number every month. Over years each has had hundreds of numbers. Sooner or later both will have had the same number at some time, by pure chance. If you only compared lists of numbers and counted the matches, you would think they shared a household.

DNA has four letters, so a match by chance is far easier: a position that changes often will land on the same letter in two unrelated lineages one time in four. The cousins with few changes are rarely matched by chance, so for them a match is better evidence of a family link.

That is the whole idea. Fast-changing, long branches produce matches that mean nothing, and parsimony cannot tell them from the matches that do.

Simple explanation with examples: counting by hand with the rule

Take the four taxa A, B, C, D with bases G, G, A, A on the tree (A,B) (C,D).

tips: A=G B=G C=A D=A pairs: {G} {A} (A,B) agree; (C,D) agree root: {G,A} {G} and {A} share nothing: 1 step

Score: one step. On the tree (A,C) (B,D) the pairs are G with A and G with A: both pairs share nothing, so each adds a step, and then {G,A} and {G,A} share states, so the root adds none: two steps. Parsimony prefers (A,B) (C,D) because it needs one change instead of two. This site is informative.

Rare genomic changes: SINE insertions as characters

A base can change again and again. A new SINE insertion at one place in one genome is a rare event. Lesson 7, section 05 shows how the same place is found in several genomes and why "copy present" or "empty site" can be written as a character; this section does not repeat that. What matters here is how such a character is read with a parsimony count.

Each locus (one place in the genome) has two states: 1, the copy is present, and 0, the empty site. The ancestral state is 0, because the copy had to arrive at some time, and reversal is rare. If two species share a copy, the simplest explanation is one insertion in their common ancestor, so they form a group. A copy in only one species says nothing about the tree, just like an uninformative base. A locus that does not fit a tree would need a second insertion or a loss. So Tree 1 is best, and locus 6 is the one that disagrees. The table is invented. In real data conflicting loci come from the causes listed under "Incomplete lineage sorting" and "homoplasy" in lesson 7, section 05, and the point is that each conflict can be seen locus by locus, as one clear observation. Nikaido, Rooney and Okada (1999) used SINE and LINE insertions this way for the even-toed ungulates and whales, and, by the abstract (read; the full text was not), concluded that whales are deeply nested within the even-toed ungulates and form a group with the hippopotamuses. For a given amount of data, rare changes like this are slow to collect, since each locus must be found, checked in the other genomes and confirmed to be at the same place, so the data sets are small compared with sequence alignments.

A SINE locus needs a different count from the DNA one. The Fitch count allows a change from 1 back to 0 as easily as 0 to 1. For SINE insertions a loss is rare, so the toy table asks only whether the sharing group is a group of the tree.

Simple explanation with examples: why an insertion is better evidence than a base

If two books have the same word on page 100, it could be because the word is common. If both have the same misprint in the same place, they were probably copied from the same book. A SINE insertion is the misprint; a base is the common word.

The comparison is not perfect. A misprint can be copied from an old edition into only some of the later ones, so a gene tree may disagree with the species tree even when nothing is wrong. That is the subject of section 10.

What to take away

  • Parsimony chooses the tree that needs the fewest changes. Fitch counting finds that number for a given tree, one site at a time.
  • Only informative sites separate trees.
  • When branches differ much in length, parsimony may join the long ones, and more data makes this worse, not better.
  • Rare changes such as SINE insertions are characters with a known direction and little chance of repeating, which suits a simple counting method.
