01From assembly to annotation: what and in which order

An assembly is a few billion letters with no labels. Annotation writes labels onto those letters: here is a repeat, here is a gene, its exons start and stop at these positions, and this gene probably makes a protein of this kind. This section explains the words, the order of the work, the one file convention every later tool depends on (soft-masking), what data to collect before you start, and how to choose a gene annotation route.

Two kinds of annotation

Structural
Where things are, as coordinates on the assembly. Three layers:
  • Repeats: transposable elements, satellites and simple repeats (sections 02 to 04).
  • Protein-coding genes: for each gene, its exons and introns, the CDS and the UTRs, and alternative transcripts (sections 05 to 07).
  • Non-coding RNA genes: genes whose product is the RNA itself, such as tRNAs and rRNAs. NCBI's pipeline EGAPx, for example, predicts rRNAs by default and tRNAs, snoRNAs and snRNAs when you switch that on. This lesson does not cover non-coding RNA genes further.
Functional
What a gene probably does: a name (for example from its ortholog in a well-studied species), the protein domains it carries, and functional terms. Section 08.

The order of the work

  1. Clean the assembly and fix the names

    Remove contamination (lesson 2, FCS-GX) and the copies of mitochondrial DNA (lesson 2, mito). Give the sequences short, simple names now (see Sequence names below). Every later file refers to these names, so changing them later means converting every file.

    EGAPx README: screen for contamination before running it · BRAKER README: "Use simple scaffold names"

  2. Repeats: build a library, then mask

    Find the repeat families of your species (03), then mark every copy in the genome (04). The result is a soft-masked genome: repeats in lowercase. Repeats come first because gene finders mistake transposable elements for genes (next part).

  3. Collect gene evidence

    RNA from the animal, proteins of relatives, an annotated relative genome. Align them to the masked genome (05).

  4. Predict or project genes

    A gene-prediction pipeline (06), a projection from a relative's annotation (07), or both.

  5. Name, check, submit

    Give genes names and domains, measure completeness, prepare files for a database (08).

  6. Side branch: heterozygosity and runs of homozygosity

    Uses the reads and the assembly, not the gene annotation, but uses the repeat mask to choose which regions to trust (09).

Simple explanation with examples: annotation as labelling a map

Think of the assembly as a satellite photo of a country with no labels. Annotation is drawing on it. First you shade the areas you know are not interesting for your question: forests that repeat the same pattern again and again (repeats). Then you draw the roads (genes) and mark where each road starts, where it is interrupted by bridges (introns) and where it ends. Last, you write names on the roads: "this one goes to the harbour" (function).

Why shade the forests first? Because from above, a long straight logging track inside a forest looks just like a road. A transposable element such as a LINE really does carry protein-coding reading frames; a gene finder that sees it unmasked will report it as a gene, and there are tens of thousands of copies.

Example from one of our rodent genomes (species A, not yet published): its largest single repeat family is a LINE-1 family with a full-length (several kb) consensus and tens of thousands of copies. Unmasked, every intact copy is a candidate "gene".

Soft-masking and hard-masking

Masking marks repeat bases in the FASTA file itself. There are two ways:

Soft-masking
Repeat bases are written in lowercase (acgt), everything else in capitals. No information is lost; a program can choose to treat lowercase as "repeat" or ignore the case. RepeatMasker writes this with -xsmall.
Hard-masking
Repeat bases are replaced by N ("unknown base"). The sequence of the repeat is gone from that file. This is RepeatMasker's default output; -x uses X instead of N.

For annotation, soft-masking is the standard. The tools say so themselves (table below). Keep one soft-masked FASTA as your master copy; you can always make a hard-masked or unmasked copy from it, but not the other way round.

# share of the genome that is soft-masked (lowercase) and hard-masked (N)
grep -v '^>' genome.sm.fa | tr -cd 'acgtn' | wc -c     # lowercase bases
grep -v '^>' genome.sm.fa | tr -cd 'Nn'    | wc -c     # N bases (assembly gaps or hard mask)
grep -v '^>' genome.sm.fa | tr -d '\n'    | wc -c     # all bases

# RepeatMasker 4.2.x: write the masked genome in lowercase instead of N
RepeatMasker -pa 16 -lib species-families.fa -xsmall genome.fa

# a hard-masked copy, only if a tool asks for one (lowercase acgt -> N)
sed '/^>/! s/[acgt]/N/g' genome.sm.fa > genome.hm.fa

# .2bit for TOGA2 / LASTZ: lowercase is kept by default (-noMask would drop it)
faToTwoBit genome.sm.fa genome.2bit

-xsmall and -x: RepeatMasker 4.2.6 help. -pa (parallel jobs) and -lib (your library) are explained in section 04. faToTwoBit options: UCSC kent source. The tr/sed lines are plain Unix tools.

Why repeats are masked before genes

Gene finders look for long open reading frames with good splice sites. Many transposable elements have exactly that, because they carry genes for their own copying enzymes. GALBA's README describes the result: if transposable elements "have not been masked appropriately, AUGUSTUS tends to predict those elements as protein coding genes. This can lead to a huge number genes." BRAKER's README gives the same reason for masking: it "will avoid the prediction of false positive gene structures in repetitive and low complexity regions." A gene set with far more genes than its relatives, where many proteins are near-copies of each other, is the typical sign. Section 08 shows how to check.

Soft-masking does not forbid genes in repeats; it only makes them less likely. Real genes can contain repeat fragments in their introns or UTRs, and a gene finder on a soft-masked genome can still place an exon there when RNA or protein evidence supports it.

What evidence to gather, before you start

  1. RNA-seq from the same species, several tissues

    Short-read RNA-seq. A gene appears only in tissues where it is switched on, so RNA from one organ shows only that organ's genes; brain, testis, liver, kidney and an embryo or whole juvenile together cover much more. For gene prediction the reads are aligned to the genome; BRAKER needs each intron "covered by many alignments", so a few well-covered libraries are better than one shallow one. Used by BRAKER3, EGAPx (05, 06).

  2. Long-read RNA (Iso-Seq, Nanopore cDNA)

    Each read is a whole transcript, so it shows which exons go together. BRAKER has a separate long-read variant that must not be mixed with short reads in one run; EGAPx accepts long reads alone or together with short reads. Its value depends on depth: BRAKER warns that accuracy "heavily depends on the depth of your isoseq data".

  3. Proteins of relatives

    Two different kinds. (a) A large protein database with many representatives of each protein family, such as the OrthoDB clade files the BRAKER team provides (Vertebrata.fa.gz at bioinf.uni-greifswald.de/bioinf/partitioned_odb12/). BRAKER requires this kind: "many representatives of each protein family must be present". (b) The proteomes of one or a few close relatives, for example from UniProt reference proteomes or NCBI RefSeq. GALBA is built for this kind.

  4. An annotated relative genome

    A related species with a good genome and gene annotation (for mammals, for example human or mouse). Its genes can be projected onto your genome through a whole-genome alignment (TOGA2, 07). This gives orthology and, uniquely, a call for each reference gene: intact, lost or missing.

The tissue list is this course's advice, not a tool requirement. Plan RNA sampling together with the DNA sampling, so that the RNA comes from the same population or, better, the same animal.

Your situation

A large protein database (OrthoDB clade file) is assumed: anyone can download it.

    Annotation files: GFF3, GTF and BED

    Gene and repeat annotations are plain tab-separated text files: one line per feature (a gene, a transcript, an exon). Three formats dominate, and the trap is that they do not count positions the same way.

    GFF3
    9 columns: sequence name, source, feature type, start, end, score, strand, phase, attributes. Positions are 1-based and inclusive: the first base of a contig is 1, and start=1, end=100 is 100 bases. Lines are linked by ID= and Parent= in column 9. The format for submission and for most pipelines' final output (Helixer, EGAPx, BRAKER with --gff3).
    GTF
    The same 9 columns and the same 1-based counting (it is GFF version 2), but column 9 says gene_id "…"; transcript_id "…";. BRAKER writes GTF unless you add --gff3.
    BED
    UCSC's format: name, start, end, and optionally up to 9 more columns. Positions are 0-based, end not included: the first 100 bases are start=0, end=100. BED12 holds a whole transcript on one line. TOGA2 writes its gene models as BED12; repeat tracks are often BED.

    One gene, three formats

    A made-up gene g1 on contig ctg1, plus strand, three exons. Pick a format and click an exon (or its line) to see the same piece in each notation.

    Never convert between these formats by hand-written awk unless you test it on a toy like this one. Converters (gffread, AGAT; section 06) know the details, such as how each tool writes phase and codons.

    Sequence names

    Contig names travel into every file: the BAM of RNA-seq reads, the repeat table, the GFF3, the .2bit, the chains. Problems the tools' own documents warn about:

    • Spaces and long descriptions. BRAKER: "If the headers are long and contain whitespaces, some RNA-Seq alignment tools will truncate sequence names in the BAM file. This leads to an error with BRAKER." Keep only the first word.
    • Dots. make_lastz_chains: "avoid dots (rename NC_00000.1 → NC_00000)".
    • Special characters. GFF3 allows any characters in the sequence name but they must be escaped unless in [a-zA-Z0-9.:^*$@!+_?-|]. TOGA2 discards reference transcripts whose names contain anything other than letters, digits, ., - and #.
    # keep only the first word of each header; letter case (the mask) is not touched
seqkit seq -i genome.sm.fa > genome.ids.fa

# optional: rename to ctg00001, ctg00002, ... and keep the translation table
seqkit seq -n -i genome.ids.fa | awk '{printf "%s\tctg%05d\n", $1, NR}' > rename.tsv
seqkit replace -p '^(\S+)$' -r '{kv}' -k rename.tsv genome.ids.fa > genome.renamed.fa

    seqkit 2.14: seq -i "print IDs instead of full headers", -n names only; replace with {kv} looks up the captured name in the two-column file -k. Keep rename.tsv with the assembly: a reviewer or database will ask which contig was which.
