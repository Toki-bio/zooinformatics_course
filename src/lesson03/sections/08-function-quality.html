08Naming genes and checking the annotation

Gene prediction (section 06) and projection (section 07) give you coordinates and protein sequences with labels like g1234.t1. This section gives those proteins names and functions, and then asks whether the whole gene set is believable before anyone uses it or you submit it.

Three kinds of evidence for a name

Domains
A protein domain is a part of a protein that folds on its own and does one job, for example binding DNA or cutting a peptide bond. The same domain turns up in many different proteins. Finding a known domain tells you what kind of protein you have ("a kinase", "a 7-transmembrane receptor"), but not exactly which one. Tool: InterProScan.
Orthology
Your protein is placed in a group of orthologs from many species, and the name and functions recorded for the closest members of that group are copied over. This tells you which gene it is, if the group is resolved finely enough. Tool: eggNOG-mapper.
Best similar known protein
Search your protein against a set of well-studied proteins and copy the name of the best hit. Simple and fast, but the best hit can be a paralog (a related gene of the same family), so the name can be wrong in a way that looks right. Tools: BLASTP or DIAMOND against Swiss-Prot.

If your genes came from TOGA2 projection (section 07), each one already carries the human (or other reference) gene symbol of its ortholog. The tools below are still useful for the genes that projection does not cover, and as an independent check.

The order of work

  1. One protein per gene
    Most predictors write several isoforms per gene. Keep the longest one for counting and naming, translate its CDS, and remove the final stop codon (*), which some tools reject.
    AGAT: agat_sp_keep_longest_isoform.pl, agat_sp_extract_sequences.pl
  2. Domains and GO terms
    InterProScan on all proteins.
    InterProScan 6.0.3.0
  3. Orthology-based names, GO and KEGG
    eggNOG-mapper on the same proteins.
    eggNOG-mapper 3.0.0-beta6 (eggNOG 7) or 2.1.x (eggNOG 5)
  4. Best hit in Swiss-Prot
    DIAMOND blastp; gives a second opinion on the name.
    DIAMOND 2.2.8
  5. Write names and terms into the GFF3
    Merge the results into the annotation file (GFF3); decide on one product name per gene.
    AGAT: agat_sp_manage_functional_annotation.pl
  6. Check the gene set
    BUSCO in protein mode, OMArk, AGAT statistics, gene counts against a relative, a look in a genome browser.
  7. Submit
    GFF3 + FASTA through table2asn to GenBank, with a registered locus_tag prefix.

Step 1: one protein per gene

# AGAT 1.7.0 (bioconda: conda install -c bioconda agat=1.7.0)
agat_sp_keep_longest_isoform.pl -gff annot.gff3 -o annot.longest.gff3
agat_sp_extract_sequences.pl -g annot.longest.gff3 -f genome.fa -p --clean_final_stop -o proteins.faa
# -p translates the CDS to protein; --clean_final_stop drops the trailing '*'

Step 2: InterProScan, domains from many databases at once

InterPro (EMBL-EBI) collects protein signatures from many partner databases, called member databases. A signature from a member database that InterPro curators have checked is grouped into an InterPro entry with an accession like IPR019805; InterPro entries carry curator-assigned GO terms and pathway links (PANTHER adds GO terms of its own). InterProScan is the program that runs all these searches on your proteins.

Member databaseWhat it finds
PfamProtein domains and families, from profile HMMs built on alignments. The most widely quoted, for example PF00078 = reverse transcriptase.
PANTHERFamilies and subfamilies of whole proteins, with curated GO terms.
CDD, SMART, PROSITE, PRINTSConserved domains (NCBI), signalling and extracellular domains, short motifs and profiles, groups of conserved motifs.
CATH-Gene3D, SUPERFAMILYStructural domains, from the CATH and SCOP classifications of known 3D structures.
NCBIFAM, PIRSF, PIRSR, HAMAP, SFLDCurated families, site rules and enzyme classes (HAMAP is mostly for microbes and organelles).
MobiDB-lite, COILSDisordered regions and coiled coils. Not families; they describe the shape of a stretch of protein.
AntiFamFamilies of spurious proteins: sequences known to be translations of non-coding DNA. A hit here is a warning about your gene model.
SignalP, DeepTMHMM, Phobius, TMbed, DeepTMHMM2Signal peptides and membrane helices. Not run by default (deep-learning tools are switched on with --run-ml); SignalP, DeepTMHMM and Phobius need a separate licence and download.

InterProScan 6 (current release 6.0.3.0, 15 October 2026) is a Nextflow pipeline that runs its tools in containers. InterProScan 5.78-109.0 (June 2026) was the last release of version 5; it will not receive new InterPro data. You need Nextflow 25.10.4 or later and Docker, Podman, Singularity or Apptainer; the member-database files are downloaded on the first run into the folder given by --datadir. For InterPro release 110.0 the archives on the EBI server add up to about 6 GB compressed (CATH 2.5 GB, PANTHER 1.0 GB, SUPERFAMILY 0.95 GB, CDD 0.48 GB, NCBIFAM 0.41 GB, Pfam 0.39 GB, the rest small); they take more space unpacked.

# first a test run: downloads data into ./ipr_data and annotates a small bundled file
nextflow run ebi-pf-team/interproscan6 -r 6.0.3.0 -profile apptainer,test \
    --datadir ipr_data --interpro 110.0

# your proteins, on a Slurm cluster; GO terms and pathways switched on
nextflow run ebi-pf-team/interproscan6 -r 6.0.3.0 -profile apptainer,slurm \
    --input proteins.faa --datadir /shared/ipr_data --interpro 110.0 \
    --goterms --pathways --cpus 8 --formats tsv,gff3,json \
    --outdir ipr_out --outprefix genome
-r, --interpro
Pin the pipeline version and the InterPro data release. The default data release is latest, and a new InterPro release comes out about every eight weeks; the documentation asks you to pin both for reproducibility.
-profile
Container runtime plus where to run: docker, apptainer, singularity; add slurm or lsf on a cluster. On a cluster --datadir and the Nextflow work folder must be on a disk that every compute node sees.
--goterms, --pathways
Off by default. Without --goterms the output has no GO terms at all.
--applications / --skip-applications
Run only some databases, for example --applications Pfam,PANTHER for a quick first pass. The two cannot be combined.
Matches API
On by default: proteins identical to one already in UniParc get precomputed results over the internet; the rest are computed on your machine. --no-matches-api forces everything local (use it on nodes without internet).

Output. genome.tsv has one line per match: protein ID, MD5, length, database, signature accession and description, start, end, score or E-value, status, date, InterPro accession and description, GO terms with their source in brackets (for example GO:0022625(PANTHER)), pathways. The .gff3 places matches on the protein for genome browsers; .json and .xml hold everything. Runtime: the documentation gives no figure, and it depends on the number of proteins, the databases chosen and the cluster. Time a run on 1,000 proteins and scale up before you book a week of cluster time.

Step 3: eggNOG-mapper, names copied from orthologs

eggNOG is a database of orthologous groups with functional terms. eggNOG-mapper finds the closest eggNOG protein to each of yours (the seed ortholog), takes the orthologs of that seed, and copies their gene name, GO terms, KEGG orthologs and pathways, EC numbers, Pfam domains and more. Its authors' point is that transferring from orthologs avoids taking a name from a close paralog, which a simple best hit can do.

Two versions in use. v3 (3.0.0-beta6, August 2026) works only with the new eggNOG 7 database (about 59 million proteins), copies only manually curated terms, and by default chooses for each protein how far up the tree to look for donors (--tax_scope auto). v2 works only with eggNOG 5; it is what conda install -c bioconda eggnog-mapper (2.1.15) and pip install eggnog-mapper (2.1.13) give you today (checked 31 October 2026). The databases are not interchangeable, and the two versions will name some genes differently. Write the version of both the program and the database in your methods.

# v3 from source (Python 3.9 or later; DIAMOND must be on PATH)
git clone --branch v3.0.0-beta6 https://github.com/eggnogdb/eggnog-mapper.git
cd eggnog-mapper && pip install .
python download_eggnog_data.py -y --data_dir /data/eggnog7      # ~45 GB
emapper.py --selftest                                             # checks the install

# annotate the proteins with the default DIAMOND search
emapper.py -i proteins.faa --itype proteins -o genome --output_dir emapper_out \
    --data_dir /data/eggnog7 --cpu 16 --temp_dir /local/scratch

# the same with the prebuilt Apptainer image (DIAMOND, MMseqs2, HMMER inside)
apptainer run --bind /data/eggnog7:/data eggnog-mapper-3.0.0-beta6.sif \
    -i proteins.faa -o genome --data_dir /data --output_dir "$PWD" --cpu 16
Database size
Core download about 45 GB: annotation database ~22 GB plus DIAMOND database ~23 GB. The optional MMseqs2 database (-M) adds ~25 GB. The free web service eggnog-mapper.cgmlab.org avoids the download for a few proteomes.
-m diamond / -m mmseqs
The search engine. DIAMOND is the default; the manual says both give the same annotations and DIAMOND is faster and lighter. MMseqs2 needs its own database. -m no_search --annotate_hits_table re-annotates an earlier search without searching again.
Memory
The manual's rough DIAMOND peak: block size × 6 + database size / index chunks + threads × 0.5 GB (in GB); both are picked from the machine's RAM when not set. Extra CPUs add little memory.
Output
genome.emapper.annotations, a 22-column table: query, seed ortholog, E-value, score, orthologous groups, taxonomic ceiling, Preferred_name, GOs, EC, KEGG columns, CAZy, BiGG, PFAMs, and annotation_confidence, one letter per annotation column (h high, m medium, l low, - none).

Step 4: a second opinion from Swiss-Prot

# Swiss-Prot, release 2026_03 (~94 MB compressed)
wget https://ftp.uniprot.org/pub/databases/uniprot/current_release/knowledgebase/complete/uniprot_sprot.fasta.gz
gunzip uniprot_sprot.fasta.gz
diamond makedb --in uniprot_sprot.fasta -d sprot
diamond blastp -q proteins.faa -d sprot -o sprot_hits.tsv --very-sensitive \
    --max-target-seqs 1 --evalue 1e-6 --query-cover 50 --subject-cover 50 --threads 16
# output format 6, the 12 BLAST tabular columns: qseqid sseqid pident length mismatch
# gapopen qstart qend sstart send evalue bitscore

--very-sensitive is meant for hits across the whole range of identities (the default mode is tuned for more than 70 % identity). --query-cover and --subject-cover keep only hits that cover at least half of both proteins, so that a shared single domain does not pass a name from a different protein. These two coverage limits are a choice, not a default. BLASTP from NCBI BLAST+ gives the same kind of table and is fine for one genome; it is slower.

Step 5: one name per gene, written into the GFF3

AGAT can copy the Swiss-Prot name into each gene's Name and each mRNA's product, and InterPro, Pfam and GO accessions into Dbxref and Ontology_term:

agat_sp_manage_functional_annotation.pl -f annot.longest.gff3 \
    -b sprot_hits.tsv --db uniprot_sprot.fasta -i ipr_out/genome.tsv \
    -o annot.func.gff3
# -b needs BLAST tabular (outfmt 6) and the same FASTA used to build the database;
# default --blast_evalue 1e-6; --pe 1..5 limits names to UniProt evidence levels

Where the three sources disagree, look before you choose. A common rule: take the ortholog name if eggNOG-mapper and the Swiss-Prot hit agree; if only a domain is found, name the protein by the domain ("zinc finger protein", "ABC transporter domain-containing protein"); if nothing is found, call it uncharacterized protein.

Naming rules you will meet

  • Product names for GenBank must be concise names, not descriptions. For a protein of unknown function NCBI accepts hypothetical protein or uncharacterized protein. A CDS without a product attribute is named "hypothetical protein" automatically by table2asn.
  • LOC numbers. In NCBI Gene a gene with no official symbol gets LOC + its GeneID, for example LOC12345 = GeneID 12345. When a real symbol is assigned later, the LOC name is replaced. You do not invent LOC names yourself; they appear when NCBI annotates a genome (RefSeq) or when your submission is processed.
  • NCBI's own pipeline names predicted genes by similarity to Swiss-Prot proteins. Most of its models that need an insertion, deletion or frameshift to keep the reading frame are labelled pseudogenes; those kept as coding get the title prefix PREDICTED: LOW QUALITY PROTEIN, because the assembly under them may have base errors. That is exactly the homopolymer problem of section 06.
  • Gene symbols. Copying a human or mouse symbol (for example from TOGA2 or eggNOG-mapper) is normal for mammals. Add nothing that claims more than the evidence: a symbol from a one-to-many orthology group means "one of the copies", not "the" gene.
Simple explanation with examples: naming strangers in an old class photo

You find a school photo with forty unlabelled faces and want a name under each.

  • Uniform (InterProScan). One child wears a football shirt: you know he played football, not his name. A domain tells you the kind of protein, for example "has a kinase domain", but there are hundreds of kinases.
  • Family tree (eggNOG-mapper). You have the family photo albums of the town. You find the child's parents and siblings, and the family records say this was the second son, Peter. Orthology places the protein in the right family and copies the name from close relatives.
  • Look-alike (best BLAST hit). You flip through a book of famous people and pick the face that looks most alike. Often right, but cousins look alike: the best hit can be a paralog, a related gene of the same family with another job.
  • "Unknown boy, back row" (uncharacterized protein). If no clue works, say so. A wrong name is worse than no name, because others will copy it.
protein g1234.t1 InterPro: IPR000719 protein kinase domain -> kind of protein eggNOG: Preferred_name MAPK1, confidence h -> which gene Swiss-Prot best hit: MK03_HUMAN (MAPK3), 85 % id -> close paralog! name chosen: MAPK1 (two orthology-aware sources agree; the best hit is a paralog)

The example protein and its hits are invented for illustration; the accessions are real InterPro and UniProt names.

Step 6: is the gene set believable?

None of the checks below proves an annotation is right. Each one catches a different kind of mistake, and each is only meaningful next to the same number for a well-annotated relative, measured the same way.

BUSCO in protein mode

BUSCO was introduced on the assembly in lesson 2, section 10. In protein mode it scores your predicted proteins instead of the genome: the FASTA goes straight to HMMER, with no gene finding. Use the one-protein-per-gene file; the BUSCO 6.1.0 user guide warns that protein sets not filtered for isoforms give many false duplicates.

busco -i proteins.faa -m proteins -l mammalia_odb12.2 -c 16 -o genome_prot \
      --download_path /data/busco_downloads --offline --opt-out-run-stats

The most useful number is the difference between genome mode and protein mode with the same dataset. Genome mode says which marker genes are in the assembly; protein mode says which of them your annotation found. If the genome scores 98 % and the proteins 90 %, about 8 % of the markers are in the DNA but the annotation missed or broke them, and so are many other genes.

OMArk: is every protein a real member of a known family?

OMArk (Nevers et al. 2025, Nature Biotechnology; version 0.5.0) looks at the whole proteome, not only a few thousand marker genes. Every protein is first placed in a gene family of the OMA database by the fast k-mer tool OMAmer. OMArk then reports:

Completeness
Like BUSCO, but on conserved HOGs of your lineage: single, duplicated (expected or unexpected, from the known history of the family) and missing.
Consistent
The protein belongs to a family known in your lineage. Sub-labels: partial hit (similar to the family over only part of its length; in the code, less than 80 % overlap) and fragmented (shorter than half the median length of that family). Both point to broken gene models.
Inconsistent
The protein matches families known from other lineages, "seemingly at random" in the words of the OMArk summary. Look at these proteins before trusting them.
Contaminant
Many proteins match the same foreign species more than expected by chance, for example a bacterium or a parasite. Compare with FCS-GX on the assembly (lesson 2, section 09).
Unknown
No similarity to any known family: an orphan gene, or a model built on non-coding DNA, for example an open reading frame inside a transposable element or a random stretch of intergenic sequence.
conda install -c bioconda omark=0.5.0 omamer
wget https://omabrowser.org/All/LUCA.h5                 # all of OMA, ~9.9 GB
omamer search --db LUCA.h5 --query proteins.faa --out genome.omamer
omark -f genome.omamer -d LUCA.h5 -o omark_out -of proteins.faa
# with all isoforms instead: add -i genes.splice (one gene per line, isoform IDs separated by ';')

The README's example on the human reference proteome takes under 15 minutes for OMAmer and under 10 for OMArk. Results: *_detailed_summary.txt (read this one), .sum, a .pdf bar chart, and with -of FASTA files of the proteins in each category, so you can look at the "Unknown" ones directly. The OMArk web server (omark.omabrowser.org) shows your result next to precomputed UniProt reference proteomes of related species, which is the comparison the authors recommend.

Counting with AGAT

agat_sp_statistics.pl --gff annot.gff3 -g genome.fa -o annot.stats.txt
# the same on a relative's RefSeq GFF3, so the two are comparable
agat_sp_statistics.pl --gff relative_refseq.gff3 -g relative.fa -o relative.stats.txt

The report lists numbers and lengths of genes, mRNAs, exons, CDS, introns and UTRs, mean exons per mRNA, Number of single exon gene and Number gene overlapping. When isoforms exist it computes everything twice, with all isoforms and with the longest isoform per gene only. Compare with a relative:

  • Gene count. Mammals share most protein-coding genes. A count far above a close relative usually means split genes (one gene predicted as two or three pieces), genes on haplotigs, or genes built from transposable elements. Far below: merged neighbours, or genes missed.
  • Single-exon (mono-exonic) genes. Real ones exist: most olfactory receptor genes have their coding sequence in one exon, and retrocopies have no introns. But open reading frames of LINE and LTR retrotransposons, and spurious predictions, are also single-exon. A share clearly higher than in the relative needs explaining.
  • Transposable-element proteins. Search the InterProScan table for TE domains, for example PF00078 (RVT_1, reverse transcriptase), PF00665 (rve, integrase core), PF02994 (Transposase_22, the L1 ORF1 protein domain), PF03184 (DDE_1, DDE endonuclease). Genes made only of these domains are most likely transposable elements that escaped masking (section 04), not host genes. Some host genes are domesticated TEs, so check by hand before removing any.
# genes with a TE domain, from the InterProScan TSV (column 5 = signature accession)
awk -F'\t' '$5=="PF00078"||$5=="PF00665"||$5=="PF02994"||$5=="PF03184"{print $1}' \
    ipr_out/genome.tsv | sort -u > te_domain_proteins.txt
wc -l te_domain_proteins.txt

Agreement with evidence: AED and transcript support

When RNA-seq or protein alignments exist (section 05), ask how many gene models they support. MAKER reports for each model an annotation edit distance (AED, Eilbeck et al. 2009): 0 means the model agrees completely with the aligned evidence, 1 means no evidence supports it. A rule of thumb from the MAKER developers is that a set is good when more than about 95 % of models have AED below 0.5; it is a mailing-list heuristic, not a published standard. Outside MAKER, the same idea is the share of models whose introns are all confirmed by spliced RNA-seq reads: compare the intron coordinates of each model with the splice junctions found by the RNA-seq aligner. Without any RNA evidence, as for our species A, this check is not available, and orthology-based checks carry more weight.

Look at it

Numbers hide patterns that a picture shows at once. Load the genome, the gene GFF3, the repeat annotation and any RNA-seq BAM into IGV or JBrowse 2, and look at about twenty random genes plus the BUSCO genes reported as fragmented or missing. Look for exons sitting inside repeats, one gene split in two at a contig end, two neighbouring genes fused into one, introns that do not match the spliced reads, and stop codons or frameshifts in homopolymer runs.

In our projects

  • BUSCO did not see the base errors. The long-read assembly of our rodent species A (not yet published, so no name or exact numbers here) scored above 95 % complete (mammalia_odb10, genome mode), at least as high as the published chromosome-level genome of a close relative. Yet inside the TOGA2 exons the reads contradicted hundreds of small indels of the assembly, nearly all of them frameshifting and most in homopolymers. They break reading frames in about one in ten genes classed "uncertain loss" and in a somewhat smaller share of those classed "lost" (our own count of gene symbols with at least one projection of that class; TOGA2's summary.txt counts lost genes by its own gene-level rule, section 07). BUSCO completeness does not measure base accuracy, and an annotation built on this assembly would carry these frameshifts.
  • Polishing did not fix it either, by this measure. In the assembly of another of our small mammals (species B), the number of BUSCO genes with internal stop codons did not fall after short-read polishing with NextPolish; it rose slightly.
  • A gene count with a reference. TOGA2 projected the 19,990 human reference genes onto species A: about nine in ten have at least one potentially functional ortholog, most of them 1:1 orthologs, and about a tenth have no ortholog found ("one2zero"). An annotation of the same genome that predicts far more genes than this would need to explain the extra ones.

Step 7: submitting the annotation to NCBI

Annotation is optional for a GenBank genome; you can submit the FASTA alone (lesson 2, section 13). If you do submit genes:

  • locus_tag prefix. Every gene needs a locus_tag. The prefix is assigned when you register the BioProject and BioSample (one prefix per BioProject-BioSample pair); annotated genomes must be registered before submission. Rules: 3-12 letters or digits, first character not a digit, case-sensitive; then one underscore and a number.
  • GFF3 in NCBI's flavour. Column 1 must match the FASTA sequence IDs. Genes need locus_tag (or give -locus-tag-prefix); mRNA needs transcript_id and CDS protein_id (or leave both out and let table2asn make them); the name goes in product= on the CDS. A broken gene that you do not think is a pseudogene, for example one with an internal stop codon, gets pseudo=true; a pseudogene gets pseudogene=<TYPE>. Partial genes are worked out automatically.
  • table2asn turns FASTA + GFF3 + a submission template into a .sqn file. The template (template.sbt) is made with NCBI's web form.
# table2asn (linux64.table2asn.gz from ftp.ncbi.nlm.nih.gov/asn1-converters/by_program/table2asn/)
table2asn -M n -J -c w -euk -t template.sbt \
    -j "[organism=Genus species] [isolate=XXXX]" \
    -i genome.fsa -f annot.func.gff3 -o genome.sqn -Z -V b
# for a scaffolded assembly also: -gaps-min 10 -l proximity-ligation (Hi-C) or -l paired-ends
# -locus-tag-prefix ABCD only if the GFF3 has no locus_tag on every gene
-M n
Genome-submission mode (validation, product-name fixes; FATAL problems reported when -Z is used).
-J, -c w, -euk
The readme says always use these with GFF3: proper protein_id/transcript_id pairs, WGS clean-up, and for eukaryotes the creation of missing mRNA features.
-Z, -V b
Write the discrepancy report (.dr) and a GenBank flatfile (.gbf) for you to read. Read the .val and .dr files before you upload; for example, the discrepancy report flags it when all proteins have the same name, which happens when products were put on the gene or mRNA instead of the CDS.
