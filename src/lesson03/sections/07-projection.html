07Annotation by projection: Liftoff and TOGA2

If a related species already has a good gene annotation, you can carry its genes over to your assembly. Each gene of the annotated genome is located in your genome, and its exons are aligned there. This is called projection. It works without RNA-seq, and it also tells you which genes look broken in your genome. That second answer is the one that needs the most care.

Words used in this section

Reference
The annotated genome you copy genes from (for us: human, or our own species A). Both tools call it the "reference".
Query / target
Your new, unannotated assembly. TOGA2 says "query", Liftoff says "target".
Projection
One reference transcript placed at one locus of the query. In TOGA2 a projection is one transcript plus one alignment chain, named transcript#GENE#chainID. One gene can have several projections (several loci, or one gene split over several contigs).
Ortholog, paralog
The same gene in two species, inherited from their common ancestor, versus an extra copy made by duplication (see lesson 2, BUSCO). Projection tools must decide which copy in the query is the true ortholog.
Processed pseudogene
A copy made when a spliced mRNA was reverse-transcribed and inserted back into the genome. It has the exons joined, without introns, and usually no promoter. It can look like an intact gene in the wrong place. If its reading frame is intact, TOGA2 calls it a retrogene candidate.
Reading frame
The grouping of coding bases into codons (three bases each). Inserting or deleting a number of bases that is not a multiple of 3 shifts the frame: a frameshift. Every codon after it is read wrongly and a stop codon soon appears.

Step 1: a whole-genome alignment, as chains

TOGA2 needs to know which part of the reference lines up with which part of the query, over the whole genome. This information is stored as chains. The UCSC Genome Browser team, who defined the format, explain it like this:

  • A gapless block is a base-for-base alignment of a piece of the reference with a piece of the query, of equal length (mismatches allowed).
  • A chain is a series of gapless blocks in the same order and on the same strand in both genomes, with gaps between them. In a single-sided gap sequence is skipped in only one genome (an insertion in one, or a deletion in the other). In a double-sided gap sequence is skipped in both (the two pieces differ too much to align).
  • A net (made by the UCSC program chainNet) is a hierarchy of chains: the best chain on top, lower-scoring chains filling its gaps. It keeps one alignment per reference region and removes pile-ups. Nets are used for liftOver of coordinates. TOGA2 takes the chain file itself as input: it wants all candidate chains, because choosing between them is part of its job.

How the Hiller lab makes chains. Their pipeline make_lastz_chains (v3.1.7, August 2026) runs LASTZ on pieces of both genomes, builds chains with axtChain, fills chain gaps with a more sensitive second alignment (RepeatFiller), and removes doubtful local alignments (chainCleaner). The final file is 07_final/<ref>.<query>.allfilled.chain.gz.

# both genomes SOFT-masked (repeats in lowercase, see section 01); no spaces or dots in sequence names
# needs Nextflow >= 25.04.6 and Docker or Apptainer
git clone https://github.com/hillerlab/make_lastz_chains.git
cd make_lastz_chains
nextflow run main.nf -params-file params.json -profile apptainer \
    --reference_genome ref.2bit --query_genome query.2bit --outdir results
#   params.json holds reference_name, query_name and the alignment settings
#   (LASTZ K=2400 L=3000 H=2000 Y=9400, chain min score 1000, gap filling, cleaning)
#   → results/07_final/ref.query.allfilled.chain.gz   (input for TOGA2)
#   resume after a crash: --from chain_antirepeat | fill_chains | clean_chains

Soft-mask first. The pipeline README asks for both genomes to be soft-masked (repeats in lowercase), not hard-masked, and suggests adding WindowMasker if LASTZ runtimes run away. Repeat masking is described in section 04. Whole-genome LASTZ between distant species is the slowest part of the whole projection approach: plan for it.

Liftoff: same or closely related species

Liftoff (Shumate & Salzberg 2020; release 1.6.3, PyPI 1.6.3.2) maps a GFF or GTF annotation between assemblies of the same species or of closely related species. It does not need chains. It cuts each gene's sequence out of the reference and aligns it to the target with minimap2. Then, for each gene, it chooses the exon alignments that give the highest identity while keeping the transcript structure. When two genes land on overlapping loci, it decides which one is mis-mapped and tries to place that one elsewhere.

# argument order: TARGET first, then REFERENCE
liftoff -g ref.gff3 -o target.gff3 -u unmapped_features.txt -p 16 \
        -copies -sc 0.95 target.fa ref.fa
#   -a 0.5 / -s 0.5 (defaults): a gene counts as mapped if its exons/CDS align with
#                coverage >= 50 % and identity >= 50 %; weaker hits stay in the GFF with
#                partial_mapping=True / low_identity=True unless -exclude_partial is set
#   -copies      look for extra gene copies not annotated in the reference
#   -sc 0.95     identity needed in exons to call an extra copy (default 1.0; must be > -s)
#   -chroms chroms.txt   lift chromosome by chromosome (lines "refchr,targetchr"); advised for
#                        chromosome-level assemblies of the same species
#   -flank 0.1   also align 10 % of flanking sequence; can help when gene structure differs
#   -polish      re-align exons to repair lost start/stop codons and in-frame stops
#                (writes target.gff3 and target.gff3_polished)

Outputs: the target annotation in the same format as the input, and unmapped_features.txt. Each gene gets sequence_ID (exon identity to the reference), coverage and valid_ORFs. Each transcript gets flags: valid_ORF, matches_ref_protein, missing_start_codon, missing_stop_codon, inframe_stop_codon. Extra copies carry extra_copy_number.

Limits, from the README: Liftoff works best when gene structure (for example intron sizes) is similar; when genes differ much in size, alignments fragment and small first or last exons are often lost. For more divergent species the README suggests raising minimap2's -r and -z through -mm2_options="-r 2k -z 5000". Liftoff reports whether the reading frame is valid, but it does not classify orthologs against paralogs or call gene losses. Use it to move an annotation between two assemblies of one species (an old and a new assembly, or two haplotypes), or between very close species.

TOGA2: orthologs and gene losses from chains

TOGA2 (Hiller lab; v2.0.10, September 2026) is the successor of TOGA (Kirilenko et al. 2023 Science). TOGA itself is no longer maintained. TOGA2 does three jobs in one run: it annotates genes in the query, decides which locus is the ortholog of each reference gene, and classifies each gene as intact, lost or missing.

  1. Inputs
    Reference and query genomes as .2bit files, the chain file, the reference annotation as BED12, and three "semi-mandatory" inputs: an isoform table (gene → transcripts), a U12 intron file, and SpliceAI predictions for the query. Since v2.0.7 you must either give each of these or set its placeholder flag (--no_isoform_file, --no_u12_file, --no_spliceai). Without an isoform file there is no gene-level result.
  2. Which chain is the ortholog?
    For every transcript–chain pair TOGA2 measures features such as: the share of the transcript's coding bases the chain aligns (gl_exo, loc_exo), the share of intron bases it aligns (intr_perc), how much of 10 kb on each side of the gene it aligns (flank_cov), and how many other reference genes the same chain covers (synt, for synteny). An orthologous locus keeps its introns and neighbours aligned; a paralog or a processed pseudogene usually does not. Two XGBoost models (single-exon and multi-exon genes) turn the features into an orthology probability; 0.5 or more counts as orthologous. Processed pseudogenes are recognised by a rule: exons aligned but introns not. A chain that spans the gene without aligning any coding base is a spanning chain.
  3. Realign each exon
    Within each locus, CESAR2 aligns every reference exon to the query, keeping the reading frame and the splice sites in view. Each exon is then Present, Missing (outside the chain, or in an assembly gap; 90 % or more N) or Deleted (neither).
  4. List the mutations
    Frameshifting insertions and deletions, premature stop codons, broken splice sites (not GT/GC…AG), and deleted or missing exons. Some are masked: recorded, but not used to call a loss (rules below).
  5. Classify
    Each projection gets a status. A transcript takes the best status among its projections, and a gene the best among its transcripts, in the order FI > I > PI > UL > L > M > (PG, PP) > N. So a gene is "lost" only if every projection is lost. Finally TOGA2 groups overlapping projections into query genes and names the orthology class: one2one, one2many, many2one, many2many, one2zero.

Masking: which mutations do not count

Frameshifts and stop codons near the ends of genes are common in conserved, working genes. TOGA2 therefore masks (records but ignores) these:

  • Mutations in the last 10 % of the reference coding sequence (C-terminal), always.
  • Mutations in the first 10 % (N-terminal) only if the query has another in-frame start codon (ATG) downstream of the mutation, still within the first 10 %. With --mask_n_terminal_mutations (-m10m), all mutations in the first 10 % are masked.
  • Two or more frameshifts that compensate each other (they add up to a multiple of 3 and there is no stop codon in the shifted stretch).
  • Deletion of a whole exon whose length is a multiple of 3 (frame-preserving); mutations inside Missing or Deleted exons; non-canonical splice sites of known U12 introns; missing start or stop codons.

The unmasking rule. In the source code (processed_segment.py, v2.0.10), masks for the first and last 10 % and for compensated frameshifts are removed again when the projection has at least one other unmasked inactivating mutation. The wiki explains the reason: a gene with one frameshift in the middle plus a terminal stop has more evidence of loss than a gene with the frameshift alone.

Toy rules (what the figure computes)
  • Masking. A frameshift or stop at codon ≥ 360 (last 10 %) is masked "C-terminal". At codon ≤ 40 it is masked "N-terminal" with -m10m, or "Alternative start found" if the ATG box is ticked and the mutation lies before codon 30. Mutations inside a deleted or missing exon are masked by that exon. A deleted exon of 135 or 297 bases is masked "Frame-preserving deletion". Frameshifts whose sizes add up to a multiple of 3, with no stop between them, are masked "Compensated".
  • Unmasking. If any frameshift, stop or frameshifting exon deletion stays unmasked, the terminal and compensation masks are lifted (code: if inactivating_found).
  • Codon string. Every codon is I (intact), L (hit by an unmasked mutation, or in an exon deleted with a frameshift), M (missing exon) or D (exon deleted in frame). From it: is the first 90 % free of L (the "middle", since the first 10 % is excluded only with -m10m)? Is the middle 80 % free of M? How long is the longest run of intact codons, as a share of all 400?
  • Classes (from classify_projection): no unmasked mutation and no missing exon → FI, or I if anything was masked. Middle free of mutations → I, or PI if missing exons reach into the middle 80 % and are < 50 % of the sequence, else M. Otherwise → L if the longest intact run is < 60 % and at least 2 exons are hit (threshold for ≤ 10 exons), else UL. Also L if fewer than 35 % of non-missing codons are intact.
  • Left out: splice-site mutations, SpliceAI, sequence identity, alternative-frame codons, the single-exon and "large exon" rules, paralogs and orthology. A compensated frameshift's codons count as intact. Real TOGA2 aligns real sequence; here you just declare the mutations.
Simple explanation with examples: copying a recipe book from a neighbour

Your neighbour has a recipe book with every recipe indexed. You have a shelf of the same recipes in a different order, and no index. Projection means: for each recipe in the neighbour's index, find the matching page on your shelf and copy the page numbers into a new index.

recipe found, all lines readable FI recipe found, last line smudged I (the C-terminal 10 % is forgiven) recipe found, a page torn out (a gap in the copy) PI or M if most is torn out recipe found, one word misprinted in the middle UL a misprint in YOUR copy, or a real change? recipe found, misprints on two different pages L two misprints on the same page UL (one page hit, not two) a photocopy glued in somewhere else, no index tabs PP processed pseudogene

The neighbour's book is the reference, your shelf is the query, and the chains tell you which shelf corresponds to which chapter. A Liftoff user copies a book of the same edition: almost every page matches. A TOGA2 user copies from a book in another language (human to mouse): pages differ, and the tool must also decide whether a missing recipe was really removed or just printed badly.

Example with numbers. A 6-exon gene, 400 codons. A 1-base deletion at codon 150 (exon 3) and nothing else: one unmasked mutation in the middle, only one exon hit, so UL. Add a stop at codon 385 (last 10 %): alone it would be masked, but the deletion unmasks it; now two exons are hit and the longest intact run is 234 of 400 codons (58.5 %, below 60 %), so L. Remove the deletion (polish the homopolymer): the stop is masked again and the gene is I.

Running TOGA2

# install: git clone --recurse-submodules https://github.com/hillerlab/TOGA2; cd TOGA2; make
#          (Python >= 3.13; Nextflow and Cargo, the Rust build tool, are not installed by make); check with: toga2.py test
faToTwoBit query.fa query.2bit
toga2.py run \
    --ref_2bit hg38.2bit --query_2bit query.2bit \
    --chain_file hg38.query.allfilled.chain.gz \
    --ref_annotation hg38.toga.bed --isoform_file hg38.toga.isoforms.tsv \
    --u12_file hg38.U12.tsv --spliceai_dir spliceai_query/ \
    --parallel_strategy local --output toga2_out
#   --min_chain_score 15000 (default) ignores weaker chains; do not go below ~1000 (wiki)
#   no SpliceAI / U12 data? set --no_spliceai / --no_u12_file instead (less accurate)
#   toga2.py prepare-input  checks and builds the reference BED/isoform/U12 files
#   toga2.py spliceai       makes the SpliceAI BigWig files for the query

What changed from TOGA to TOGA2 (wiki and preprint, Malovichko et al. 2026 bioRxiv): the new FI class; the old "partially missing" class removed (now UL or M); processed pseudogenes and retrogene candidates as their own class; SpliceAI used for splice-site shifts and new introns; UTRs added; exon-wise annotation that the preprint reports uses 513-fold less memory and runs 6.1 times faster; masked terminal and compensated mutations now count towards L once another unmasked mutation exists.

Why every "lost" gene needs checking

TOGA2's L means: in this assembly, no projection keeps an intact reading frame. Several things other than real gene loss give the same result:

  • Base errors in the assembly. A 1-base indel in a homopolymer (a run of one base, like GGGGG) is a frameshift. Long-read assemblies carry such errors unless polished (lesson 2, polishing). One error gives UL; two in different exons give L.
  • Assembly gaps. TOGA2 calls an exon Missing, and a gene spanned by an unaligned chain gap M rather than L, only when the query sequence there contains Ns. Gaps still matter for every follow-up test (see the flank example below).
  • The other haplotype. A primary assembly holds one copy of each region; the intact allele may be in the other haplotype.
  • Paralogs and gene families. Large families of similar genes, such as immunoglobulin and T-cell receptor segments, make the ortholog hard to pick.
  • Real divergence. An exon too different to align can be reported as deleted.

Look at inactivating_mutations.tsv for each candidate: are the events in homopolymers? Do the reads agree with the assembly at those bases? Is there a gap nearby? Only events that survive these checks support a loss. The same base errors also break gene models from ab initio predictors (section 06), and BUSCO completeness does not reveal them (section 08).

In our projects

  • Human → our rodent species A, run by the Hiller lab (species A is not yet published, so no name or exact numbers here; TOGA2 v2.0.8e, LASTZ chains, --min_chain_score 15000, with SpliceAI and U12 files). summary.txt: most of the 19,990 human reference genes have at least one potentially functional ortholog, the large majority as 1:1 orthologs, plus about a thousand retrogene candidates; around a thousand genes are called lost and a few dozen missing. Among projections, more than half are FI, about a fifth UL, and I, L, PI and M follow with smaller shares. The BED colour counts agree with the wiki colour table.
  • Read the summary critically. Its gene-level percentages are divided by the number of projections, not by the 19,990 genes, so the share of FI genes is printed far too low. And "reference genes considered present" repeats the transcript-level number.
  • The frameshift caveat. Variant calls from our own reads found hundreds of simple indels inside TOGA2's exons that the reads contradict: nearly all shift the frame and most are homopolymer-type. Genes with at least one such false frameshift: about one in ten UL genes, somewhat fewer L genes, a few per cent of I genes and almost no FI genes. About half of the "lost-only" genes carry a read-contradicted indel or a homopolymer that differs from the close relative. Our recorded decision: polish with our own reads and rerun TOGA2 before interpreting the lost-gene list.
  • One bad base versus several defects (one class-L gene). One frameshift deletion sits in a G5 homopolymer, and the reads are split on its length (only about a third support the assembled length). But the gene has two more unmasked events outside homopolymers and not contradicted by the reads (a frameshift insertion in exon 1, a TAG stop in exon 3). It stays lost even if the G run is corrected. The toy's "three events" example copies this pattern.
  • Species A → a published close relative, our own run. Human-vs-relative LASTZ was abandoned: one test pair (human chr21 against a 17-Mb piece) took more than 1.6 CPU-hours, so the whole genome would take weeks. For the close pair we used minimap2 (-c --cs -x asm10) and turned its output into chains with transanno minimap2chain; that tool gives every chain the score 4900, so chains had to be rescored (chainScore -linearGap=medium, then chainSort). This is experimental: minimap2 chains are not validated for TOGA2. The reference was the intact species A transcripts from the Hiller run, so genes lost in species A could not be tested. Among the gene results, the largest group was N: reference transcripts rejected at setup (thousands had a coding length not divisible by 3), which says nothing about the relative's genome.
  • Lost is not deleted (a flank test). To ask whether an L or M gene is really gone, we use the sequence flanking the gene as anchors in the relative's genome (close species only): if both flanks are found next to each other with nothing between, the site is empty. Of several hundred L+M genes, about a third were found present, similar numbers had no anchor or only one flank, and just 2 looked empty; many lie in immunoglobulin and T-cell receptor segments, where flanks are not unique. Both "empty sites" were false: a 100-N scaffolding gap lay a few hundred bases away. HiFi reads spanning the site confirmed a homozygous deletion for one gene; two others look heterozygous (reads support both versions; a paralog is not excluded).

Which tool when. Same species, new assembly or other haplotype: Liftoff. Close or distant species with a good reference annotation, and you also want orthologs and loss calls: TOGA2 (needs chains; for distant pairs LASTZ chains are the tested input). In both cases the projected genes are only as good as the bases of your assembly: polish first. Projected genes can also serve as evidence for gene prediction (section 05, section 06).
