03How exact search works

Section 02 used grep and agrep as black boxes. This section opens them. There are five ideas: the naive scan, Boyer-Moore skipping, Knuth-Morris-Pratt, Aho-Corasick for many patterns, and bitap for errors. Each one saves a different kind of work. At the end we say which of them the two programs really use, as read in their source code.

The naive scan

Put the pattern under the start of the text. Compare letter by letter from the left. At the first difference, move the pattern one position to the right and start again. An alignment here means one such placement of the pattern against the text, with no gaps.

This is correct, and on random DNA it is not terrible, because most alignments fail at the first or second letter. The trouble is repeats. Search for AAAAAB in a long run of A and every alignment costs the full pattern length. Boyer and Moore, citing Knuth, Morris and Pratt, put the worst case at a number of comparisons "on the order of i * patlen": the position reached times the pattern length. Genomes are full of such runs (lesson 3, s02).

Knuth-Morris-Pratt: never go back in the text

The naive scan forgets. Suppose the pattern is ATATC and the text reads ATATA…. The first four letters matched and the fifth failed. You already know the last two letters read were AT, and that is how the pattern begins. So slide the pattern and go on from the letter where you stopped, without reading anything twice. How far to slide depends only on the pattern, so it can be worked out once, before the search. In Boyer and Moore's summary, this algorithm "inspects each of the first i + patlen - 1 characters of string precisely once".

That guarantee removes the worst case, but every letter is still read. Remember the idea of a prepared table of "where to fall back to". It comes back in Aho-Corasick.

Boyer-Moore: compare from the right, then jump

Boyer and Moore (1977) changed one thing: compare from the last letter of the pattern. If the text letter there does not occur in the pattern at all, no alignment that covers this letter can work, so the pattern jumps its whole length past it. The letters jumped over are never looked at. Two prepared tables decide the jump, and the larger one wins:

Bad-letter rule
Look at the text letter that caused the mismatch. Slide until the nearest copy of that letter in the pattern lies under it. If the pattern does not contain the letter, slide past it. The paper calls this table delta1.
Good-suffix rule
The tail of the pattern has already matched. Slide until that same tail can line up again, preceded by a different letter. The paper calls this table delta2.

The paper's own figure: "For a random English pattern of length 5, the algorithm will typically inspect i/4 characters of string before finding a match at i". The longer the pattern, the longer the jumps. The authors call this "usually sublinear": it reads fewer letters than the text contains. The file must still be read in from disk, so the saving is in the work done per letter, not in the reading (s05 shows when reading becomes the limit).

The DNA example shows the catch. With four letters, nearly every text letter occurs somewhere in the pattern, so the bad-letter jumps stay short. The check at the end of this section measures it on random text. The naive scan makes about 1.3 comparisons per text letter on DNA and 1.04 on 26 letters. When we ask for every occurrence and they overlap, Boyer-Moore does as many comparisons as the naive scan.

Simple explanation with examples: why starting from the right lets you skip

You look for the word TIGER in a long line of print, and you hold a card with a five-letter window. Look only at the last letter in the window. It is Q. There is no Q in TIGER, so none of the next five placements of the word can cover this Q. Move the card five letters at once. You have checked one letter and passed five.

If the letter is G, it is in the word, third from the left. Move the card two letters, so that the G of TIGER lies on it, and look again.

Starting from the left gives you much less. A first letter that differs only tells you this one placement failed, so you may move by one.

Aho-Corasick: many patterns in one pass

Now you have fifty primers, or a thousand adapters. Running one search per pattern reads the text fifty times. Aho and Corasick (1975) build one machine from all the patterns and pass the text through it once. They say their approach "combines the ideas in the Knuth-Morris-Pratt algorithm" with those of finite state machines. Three parts make up the machine:

Goto (the trie)
All patterns are stored in one tree of letters, a trie. Patterns that start the same share a path. Each node is a state, and a state means "the last letters read spell this path".
Failure links
When the next letter has no edge, the machine does not start over. It follows a link to the state for the longest ending of what it has read that is also the start of some pattern. This is the Knuth-Morris-Pratt fall-back, for many patterns at once.
Output
Each state lists the patterns that end there, including shorter ones hidden inside. In the DNA example, state 8 reports ATCG and also TCG.

The paper states the two costs. Building the machine "takes time proportional to the sum of the lengths of the keywords". And "the number of state transitions made by the pattern matching machine in processing the text string is independent of the number of keywords". So a thousand patterns cost about the same text pass as one, but each letter is read: Aho-Corasick does not skip.

Bitap: all partial matches at once, and errors for little extra

All the methods so far need exact equality. Wu and Manber (1991) needed something else: a match within k errors, where an error is one substitution, insertion or deletion. That count is the edit distance. Their method builds on the shift-or idea of Baeza-Yates and Gonnet. The routine in agrep is called bitap, and we use that name.

Keep one bit per pattern position. Bit i says "the first i letters of the pattern match the text ending just here". Prepare one mask per letter of the alphabet, with 1 wherever that letter occurs in the pattern. For each text letter the whole state changes with two machine operations: "a shift and an AND". The shift extends every partial match by one position, and the AND keeps those where the new letter fits. All partial matches advance together, so no alignment is tried on its own. Shift-or is the same thing inverted: as Wu and Manber describe it, Baeza-Yates and Gonnet "used 0 to indicate a match and an OR operation instead of an AND".

Baeza-Yates and Gonnet could count mismatches only; Wu and Manber added insertions and deletions. For errors, keep k + 1 such rows. Row d holds the partial matches with at most d errors. Wu and Manber fill it from four cases: a matching letter from row d, and a substitution, a deletion or an insertion from row d − 1. That is a few more machine operations per row, and the rest stays the same.

Two limits follow. The state must fit in a machine word, or the work grows: "the discussion above assumes, of course, that the pattern's size is no more than the word size". And every text letter is processed. In exchange the time is steady: it "depends only on the size of the text (assuming again that the pattern fits into a word) and not on the actual text or the alphabet". Repeats do not hurt it.

Simple explanation with examples: bitap worked out for the pattern CAT

Pattern CAT, text GCATCGT. Each row is one beginning of the pattern, and each column is one text letter. A 1 means "this beginning of the pattern ends here". The first three rows allow no error. The last three allow one.

text G C A T C G T 0 errors C 0 1 0 0 1 0 0 CA 0 0 1 0 0 0 0 CAT 0 0 0 1 0 0 0 1 error C 1 1 1 1 1 1 1 CA 0 1 1 1 1 1 0 CAT 0 0 1 1 1 0 1

Read the CAT rows. With no errors there is one hit: the exact word ends at the fourth letter. With one error the row shows that end and three others. The third letter gives CA, with the T deleted. The fifth gives CATC, with a C inserted. The last letter gives CGT, with A replaced by G. The machine does not say which error it was, only that some alignment ending here needs at most one.

We ran this recurrence against a plain edit-distance calculation on 20,000 random DNA pairs, and all 563,632 end positions agreed.

Bitap is not the only way to allow errors. If a pattern is cut into k + 1 blocks, then at most k errors cannot touch all blocks, so at least one block occurs exactly. A fast exact search for the blocks finds candidate places, and only those get the expensive check. Wu and Manber use this partition in agrep. It is the same logic as the seeds of s07.

What the programs really use

You will read that grep uses Boyer-Moore. The truth depends on the options. We read the source of GNU grep (development version after release 3.12) and the kwset module of gnulib, which holds its fixed-string search. The comment in kwsprep says it in one line: "Use Boyer-Moore if just one pattern, Aho-Corasick otherwise."

Its error count stops at 8 ("the maximum number of errors is 8"). TRE's agrep takes another road. Its README says it "allows full regexps of any length, any number of errors, and non-uniform costs". Its approximate matcher, tre_tnfa_run_approx, walks an automaton built from the regular expression and keeps costs for each reached state. It uses no bit masks, so it is not bitap at all.

For sequences the lesson is about scale. A 200-bp SINE copy with 15 % differences has 30 errors. The Wu-Manber program refuses that. And a plain count of errors treats all differences alike, which is a poor measure of "related". Sections 06 and 07 replace it with a score. If the question is not "where is this string" but "which of these k-mers", the next section's hash tables do better.
